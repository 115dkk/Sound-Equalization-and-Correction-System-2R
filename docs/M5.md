# M5 이식 지도: 화면

M5는 SECS 2R에 화면을 붙이는 단계입니다. M4까지 서비스와 CLI가 측정부터 내보내기까지 한 바퀴를 돌므로, 이 단계의 일은 사람이 그 길을 화면에서 걸을 수 있게 하는 것입니다. [`ARCHITECTURE.md`](ARCHITECTURE.md) 7절과 8절의 M5 행, [ADR 0003](adr/0003-stack-and-ipc.md)의 화면 규칙을 여기서 작업 단위로 나눕니다. 업스트림 화면에서 사용자가 보고 누를 수 있는 것은 [`M5-inventory.md`](M5-inventory.md)에 모두 적었습니다. 이 단계가 끝나면 그 목록의 항목마다 새 화면에서 닿는 자리가 있어야 합니다.

## 1. 업스트림에서 알게 된 것

- **화면은 일곱 칸 진행 막대입니다.** 장치·마이크, 구성, 레벨 체크, 배치, 측정, 보정 설계, 내보내기 순서입니다. 칸마다 다음으로 넘어갈 수 있는지와 그 이유를 화면이 판정하고, 아래 막대 가운데에 이유 한 줄을 띄웁니다.
- **설정의 정본이 흩어져 있습니다.** 장치 설정은 `extra['devices']`, 배치는 `extra['array']`, 레벨은 `extra['levels']`, 보정 설정은 `extra['calibration']`, 내보내기 폴더는 `extra['export']`, 타겟은 `project.target`과 `bc['target_preset']`에 있습니다. 새 화면도 같은 자리를 읽고 씁니다. 저장 바이트가 SECS 2와 같아야 하기 때문입니다.
- **결과를 말하는 자리가 많습니다.** 아래 막대, 1단계 안내 상자, 2단계 오류 상자, 5단계 로그, 보정 상태 줄 셋, 내보내기 메모, 튜토리얼 토스트가 모두 따로 말합니다. 알림을 모으는 곳이 없습니다.
- **기다림 표시가 셋입니다.** 오른쪽 아래 작업 패널, 화면을 덮는 로딩 카드, 작은 물방울입니다. 로딩 카드의 [취소]는 아무것과도 이어져 있지 않습니다.
- **숨겨진 기능과 죽은 기능이 있습니다.**
  - 숨겨진 것: 바이앰프 화면(`BIAMP_UI=False`), 영어 화면(`ENGLISH_UI=False`), 초고지연 모드(설명 줄을 3초 안에 다섯 번 눌러야 열림), 단계별 mdat 내보내기 카드(만들기만 하고 보이지 않음).
  - 죽은 것: 마지막 단계의 '완료' 단추, 엔진이 읽지 않는 DSP 프로필 칸(U2~U4).
- **튜토리얼은 화면 위에 덧씌운 퀘스트입니다.**
  - 퀘스트는 마흔 개 남짓입니다. 종류는 '보기'와 '해 보기'이고, 모의 REW와 데모 방, 미리 계산해 둔 결과를 씁니다.
  - 표적을 감싸는 테두리, 코치 카드, 퀘스트 목록, 일시정지가 있습니다.
- **그래프는 다섯 가지입니다.**
  - 측정 곡선(로그 축, 1/12 옥타브)
  - 보정의 SPL·GD·XO·BA 탭
  - 그 밖에 레벨 미터와 배치도 셋이 있습니다.

## 2. 화면 지도

새 화면은 다섯 단계 레일입니다(`ARCHITECTURE.md` 7절). 업스트림의 일곱 칸은 이렇게 들어갑니다.

| 레일 단계 | 업스트림 화면 | 비고 |
|---|---|---|
| 시스템 | 구성(2), 배치(4) | 스피커·출력 패치·DSP 프로필과 측정 위치 배치를 한 단계에서 정합니다. 배치는 측정 계획이라 구성 옆에 둡니다. |
| 연결·점검 | 장치·마이크(1), 레벨 체크(3) | 측정 방식(자체 측정, REW, 모의)을 먼저 고릅니다. mdat 가져오기만 할 사람은 이 단계를 건너뜁니다. |
| 측정·가져오기 | 측정(5) | 위치 목록, 배치도, 측정 곡선, mdat 가져오기와 파일 관리, 데모 데이터 |
| 보정 | 보정 설계(9) | 판정 카드 → 채널별 성적표 → 그래프(SPL, GD, XO, BA) 순서. 설정은 모드, 보정 범위, XO, 서브(BA), MIMO 절로 나눕니다. |
| 내보내기 | 내보내기(8), 숨은 내보내기 카드 | CamillaDSP와 전후 mdat이 주 경로이고, 단계별 mdat은 '고급'에 둡니다(U3). '완료' 단추는 없습니다(U4). |

화면 전체에 걸치는 것은 다음과 같습니다.

- **앱 틀.**
  - 레일과 프로젝트 상태 줄이 있습니다. 상태 줄에는 구성 요약, 측정 위치, 보정 상태, 측정 경로 상태, 파일 이름을 보입니다.
  - 프로젝트 새로 만들기·열기·저장·다른 이름으로 저장이 있습니다. 새로 만들기는 업스트림에 단추가 없던 것입니다.
  - 닫을 때 저장할지 묻습니다.
  - 언어(한국어·영어), 테마와 로고는 사용자별로 기억합니다. 세부 설정은 해당 기능에서 펼칩니다(P58).
  - 단축키는 업스트림과 같은 자리에 둡니다(Alt+←/→, Ctrl+1…5, Ctrl+S, Ctrl+Shift+S, Ctrl+O, F1).
- **작업 트레이.** 업스트림의 작업 패널, 로딩 카드, 물방울을 하나로 모읍니다. 도는 잡마다 이름, 진행, 경과·예상 시간, 실제로 멈추는 취소 단추가 있습니다. 서비스의 잡 이벤트(`Started`, `Progress`, `Log`, `Finished`)를 그대로 그립니다.
- **알림.** 잡의 `Log`와 오류는 트레이의 기록에 모입니다. 오류 문구는 원인과 다음 행동을 적고, 원문은 '자세히'에 둡니다(ADR 0003).
- **도움말.** 업스트림 `tutorial_text.py`의 단계별 도움말(따라 하기, 확인할 것, 문제 해결, 실제 REW, mdat 가져오기, CamillaDSP)을 새 화면에 맞게 다시 씁니다. 업스트림 화면 사진은 쓰지 않습니다.
- **튜토리얼.** 모의 측정과 샘플 프로젝트(M4)를 그대로 씁니다. 퀘스트의 '보기'와 '해 보기', 코치 카드, 퀘스트 목록, 일시정지, 용어 풀이를 옮깁니다. 표적은 화면 요소의 안정된 id로 가리킵니다.

## 3. 서비스에 더할 것

M4의 IPC는 측정·보정·내보내기를 돌리지만, 화면이 고치는 설정과 그래프가 그리는 곡선을 아직 주고받지 않습니다. 메서드마다 `features.toml`에 `ipc.<메서드>`를 둡니다.

| 묶음 | 메서드(가칭) | 업스트림 | 작업서 |
|---|---|---|---|
| 구성 | `config_get`, `config_apply_preset`, `config_set_sub_count`, `config_set_speaker`, `config_add_speaker`, `config_remove_speaker`, `config_renumber`, `config_validate`(코드와 인자), `patch_sheet_csv` | `step2_config.py`, `model.SpeakerConfig` | P26 |
| DSP 프로필 | `dsp_get`, `dsp_set`(프리셋 또는 칸별) | `DspProfile` | P26 |
| 배치와 측정 옵션 | `layout_get`, `layout_set`(배치, 시작 지연, 타이밍 레퍼런스), `position_estimate` | `step4_layout.py`, `timing.py` | P26 |
| 타겟 | `target_get`, `target_set_points`, `target_apply_preset`, `target_save`, `target_load` | `target_editor.py` | P26 |
| 보정 설정 | `calibration_settings_get`, `calibration_settings_set`, `mode_spec` | `CalibrationSettings`, `cal.mode_spec` | P26 |
| 앱 설정 | `app_settings_get`, `app_settings_set`(언어, 테마, 로고, 계산 장치, 최근 프로젝트, 창 크기) | 없음(새 기능) | P26, P58 |
| 측정 곡선 | `measurement_curves`(1/12 옥타브, 280점, 200–2000 Hz 평균 0 dB) | `step5_measure.py:501-515` | P27 |
| 결과 곡선 | `result_curves { tab: spl\|gd\|xo\|ba, channel, group, xo_hz }`(타겟 기준 레벨 이동, RC 경계 포함) | `step_calibration.py:2144-2401` | P27 |
| 서브(BA) | `calibrate { subs_only }`, `sub_take_values`, `sub_warnings`, `sub_table` | `cal.sub_combine`, `take_sub_values`, `sub_*_warnings` | P27 |
| 레벨 모니터 | `level_monitor_start`, `level_monitor_stop`, `level_play`(분홍 잡음, 서브는 50 Hz) 이벤트로 레벨을 밀어 보냄 | `step3_level.py`, `mic_meter.py` | P28 |
| 호스트 | 파일·폴더 대화상자, 폴더 열기, 알림(Tauri 플러그인), 내보내기 폴더 이름(`SECS_mdat_<…>_<모드>_<시각>/`) | `window.py`, `step8_mdat.py` | P28 |
| 측정 경로 감시 | 측정 경로 상태 이벤트(REW 실행·API·Pro, 자체 측정 장치 목록 변화) | `rew_cache.py` | P28 |

같은 결과를 업스트림이 계산하는 함수(곡선 평활, 레벨 이동, XO 미리보기, 서브 합, 경고, 모드 설명, 시간 추정)는 오라클 가족 `service_curves`로 맞춥니다. 화면은 곡선을 받아 그리기만 하고 수치를 계산하지 않습니다.

## 4. 화면의 재료

- **토큰.**
  - CSS 사용자 정의 속성 하나로 색, 글자, 간격, 반지름, 그림자, 움직임을 정합니다(ADR 0003: 두 번째 스타일 체계 없음).
  - 밝은 테마와 어두운 테마를 같은 토큰에서 냅니다. 기본값은 운영체제를 따릅니다.
  - 강조색은 하나입니다. 튜토리얼은 강조색만 바꾼 변형입니다.
  - 채널 색 순서와 곡선 선 굵기 규칙(서브 굵게, 위치 1 굵게)도 토큰입니다.
- **구성 요소.** 카드, 절(접는 '고급' 포함), 알약 상태 표시, 단추 위계(주 동작 하나), 숫자 칸(단위, 범위, tabular-nums), 고르기, 증감기, 토글, 표(묶음 머리줄), 레벨 미터, 진행 막대, 토스트, 대화상자, 툴팁(800 ms, 폭 제한)을 둡니다.
- **그래프.**
  - uPlot을 쓰고 로그 주파수 축을 둡니다. 고정 눈금은 5, 10, 20, 50 … 20k입니다.
  - 범례와 위치 칩, 축 범위 팝오버가 있습니다.
  - 타겟 점 편집(끌기, 두 번 눌러 더하기, 빼기)과 XO 선 끌기를 지원합니다.
  - 곡선 수십 개, 점 수천 개에서 끊기지 않아야 합니다.
- **배치도.** 직접 그린 SVG입니다. 방 배치도(스피커 표식, 고르기), 측정 배치도(위치 표식, 완료와 현재, 키보드 이동), 작은 배치도를 그립니다.
- **문구.**
  - 화면은 키만 씁니다. `ko`와 `en` 카탈로그를 함께 고치고, 키 집합과 자리표시자가 같아야 합니다(화면 테스트).
  - 한국어가 원문이고, 문장은 합니다체, 라벨은 명사구로 씁니다.
  - 서비스의 코드와 인자(`Notice`, 오류 코드, 잡 `Log`)를 문장으로 만드는 표도 카탈로그에 둡니다.

## 5. 이번 단계의 편차

| 번호 | 내용 |
|---|---|
| U2 | DSP 프로필 칸을 '내보낼 DSP'로 이름 붙이고, 그 값이 쓰이는 곳(FIR 예산 경고, MIMO FIR 예산)을 화면에 적습니다. |
| U3 | 단계별 mdat 내보내기를 내보내기의 '고급'에 되살립니다. |
| U4 | 아무 일도 하지 않던 '완료' 단추를 없앱니다. |
| U6 | SNR 경고 문턱을 하나로 맞춥니다. 코드의 20 dB를 따르고 도움말 문구를 고칩니다. 업스트림 의도를 이슈로 묻고 답이 오면 따릅니다. |
| U7 | 영어 화면을 처음부터 냅니다(업스트림은 `ENGLISH_UI=False`). |
| U8 | 기다림 표시 셋을 작업 트레이 하나로 모읍니다. 로딩 카드의 이어지지 않은 [취소] 대신 실제로 멈추는 취소를 둡니다. |
| U9 | 초고지연 모드를 다른 보정 모드와 같은 선택 목록에서 고릅니다(P58). |

바이앰프 화면은 업스트림이 닫아 두었으므로 이 단계에서도 열지 않습니다. 업스트림이 열면 따라갑니다.

## 6. 판정

- **닿는지.** `M5-inventory.md`의 항목마다 새 화면의 자리(화면 요소 id)를 적은 대조표 `docs/M5-reach.md`를 두고, 화면 테스트가 그 id들이 실제로 그려지는지 확인합니다. 대조표에 빈칸이 없어야 끝납니다.
- **화면 갤러리.** 모의 서비스로 화면마다 상태별(비었음, 진행 중, 완료, 낡음, 오류, 튜토리얼) 그림을 그리는 갤러리 페이지를 둡니다. CI가 Playwright(사전 설치 Chromium)로 밝은 테마와 어두운 테마, 한국어와 영어를 찍어 산출물로 남깁니다. CI 설계는 Claude가 합니다.
- **화면 리뷰.**
  - make-interfaces-feel-better 규칙으로 갤러리를 검토하고, HIGH가 없어야 합니다.
  - 리뷰는 구현한 쪽과 다른 쪽이 합니다. Opus 5.5가 그린 화면은 Claude가 보고, 감사는 ASTRA가 읽기 전용으로 합니다.
- **연결.** 화면이 부르는 IPC는 모두 생성된 바인딩의 타입으로 부릅니다. 서비스와 화면을 잇는 흐름 하나(샘플 프로젝트 → 데모 데이터 → 보정 → 내보내기)를 Tauri 없이 화면 테스트에서 모의 IPC로 돌립니다.
- **문구.** 카탈로그의 키 집합과 자리표시자 일치, 쓰이지 않는 키 없음, 14px 하한(토큰 테스트)을 확인합니다.

## 7. 순서

```text
P26 구성·설정 메서드(Daybreak) ─┐
P27 곡선·서브 메서드(ASTRA) ────┼─ P33 화면 연결(ASTRA) ─ P35 튜토리얼 퀘스트 ─ P34 카탈로그(ASTRA) ─ 갤러리 리뷰 ─ M5 끝
P28 호스트·모니터(Daybreak) ────┘        │
P29 토큰·틀·구성 요소·갤러리(Opus) ─ P30 시스템·연결·점검 화면(Opus)
                                     P31a 측정·가져오기 화면(Opus)
                                     P31b 보정 화면(Opus)
                                     P32 내보내기·도움말·튜토리얼 엔진·프로젝트 대화상자(Opus)
```

- P26, P27, P28, P29는 겹치는 파일이 없어 나란히 돕니다.
- P29는 서비스 없이 모의 IPC로 그립니다.
- P30~P32는 P29의 구성 요소 위에서 화면별로 나눠 나란히 돕니다. 공통 계약은 [`packets/M5-screens-common.md`](packets/M5-screens-common.md)입니다. 화면은 `view`를 받아 그리고 `actions`로 알리기만 하며, P26~P28의 바인딩 타입을 쓰되 실제 호출 연결은 P33이 합니다.
- 튜토리얼은 화면이 선 뒤에 그 위에 얹습니다. 엔진(덮개, 코치 카드, 퀘스트 목록, 용어 풀이)은 P32, 업스트림 퀘스트 마흔여 개를 새 화면의 id로 옮기는 일은 P35입니다.

## 8. 끝나는 조건
