# P55. 설정을 먼저 읽고, 설명은 필요할 때 연다

기준: main `25018cd` (0.20.0), 브랜치 `codex/contextual-help`.
근거: ADR 0003, `docs/DESIGN.md`, make-interfaces-feel-better의 `write.md`.

## 사용자 목표

설정은 라벨·선택지·단위·현재값만으로 조작할 수 있어야 합니다. 화면을 차지하는
정적 설명은 해당 설정이나 묶음의 툴팁으로 옮기고, 효과와 선택 기준을 짧게 씁니다.
기존 문단을 그대로 긴 말풍선에 옮기는 방식은 피합니다.

## 소유권

- 화면 워커: `apps/secs2r/ui/src/`의 공통 UI·앱 틀·화면·견본·관련 테스트.
  `src/i18n/ko.json`, `en.json`과 생성 IPC 바인딩은 제외합니다.
- 문구 워커: `src/i18n/ko.json`, `en.json`. 화면 워커와 키·자리표시자를 조율합니다.
- 독립 감사: 동적 상태·필수 안내의 보존과 접근성 회귀 위험을 읽기 전용으로 검토합니다.
- 조정자: 설계 문서·작업서·변경 기록·리뷰와 증거, 독립 검증·커밋·PR·머지·릴리스 확인.

공유 작업 공간입니다. 다른 담당자의 편집을 되돌리지 않으며 커밋은 조정자가 합니다.
기존 E: 체크아웃, 업스트림 Python, DSP·IPC·설정 동작은 수정하지 않습니다.

## 화면과 도움말 계약

1. 시스템, 연결·점검, 측정·가져오기, 보정, 내보내기, 프로젝트 대화상자와 앱 설정을
   기본·고급·전문가 상태까지 점검합니다. 전용 도움말과 튜토리얼의 본문은 유지합니다.
2. 정적 보충 설명에는 명시적인 `help` 속성이나 공통 도움말 트리거를 사용합니다.
   `hint`·`description` 전체를 일괄 숨기지 않습니다. 숫자 입력·선택·토글·분할 선택과
   카드·섹션·단계 머리에 일관된 표시 방식을 적용합니다.
3. 각 라벨과 선택지는 설명 없이도 대상을 식별해야 합니다. 단위와 선택 상태는
   보이고, 중복 설명과 조작 방법을 되풀이하는 문장은 줄입니다.
4. 필드 툴팁은 1–2문장으로 무엇이 바뀌는지, 언제 선택할지, 필요한 경우 손익을 설명합니다.
   여러 측정 방식의 요구 조건처럼 비교가 필요한 내용은 짧은 항목 목록으로 묶습니다.
   사용자에게 필요한 오디오 용어는 유지하고 내부 설정 키·상태 기계 용어는 사용하지 않습니다.
5. 현재값·권장값·측정 위치·예상 시간·실제 계산 모드·진행·낡음·오류·복구 동작·사용 불가
   사유는 화면에서 읽을 수 있어야 합니다. XO 추천 주파수, 서브 현재 구성,
   MIMO 위치 수와 최소 조건, 음향 타이밍의 반복 측정 제한 등이 여기에 해당합니다.
6. 비활성 입력의 도움말도 열 수 있어야 합니다. 읽기 위해 설정값을 바꾸거나 작업을
   시작할 필요가 없어야 합니다. 라벨 연결과 입력의 접근 가능한 이름을 보존합니다.
7. 마우스 hover, 키보드 초점, 명시적 클릭/터치로 도움말을 열 수 있습니다. Escape와
   바깥 클릭으로 닫고, 도움말 위로 포인터를 옮겨 읽을 수 있습니다. 도움말을 닫는
   Escape가 부모 대화상자까지 닫지 않아야 합니다. 화면 가장자리·스크롤·크기 변경을 처리합니다.
8. 도움말은 기존 14px UI 글자와 색 토큰을 사용합니다. 좁은 창과 긴 영어 문구에서
   잘리지 않아야 하며, 도움말 트리거의 누름 영역이 옆 설정이나 다른 트리거와 겹치지 않습니다.
9. 한국어·영어의 의미·키·자리표시자를 맞춥니다. 문장은 합니다체, 라벨은 명사구이며
   한 설정의 이름은 화면과 도움말에서 일관되어야 합니다.

## 검증과 완료 조건

- 의미 있는 공통 도움말 상호작용 테스트: 열기·닫기, 키보드·터치, hover 유지,
  Escape 우선순위, 비활성 설정, ARIA 연결, 값 변경 없음.
- 기존 필수 상태/오류/추천값/조작 테스트가 유지되고 두 언어 카탈로그 검사를 통과합니다.
- 타입 검사, 전체 UI 테스트, 앱·갤러리 빌드와 화면 투어를 독립 실행합니다.
- 동일한 화면 상태를 ko/en·밝게/어둡게로 비교하고, 주요 도움말의 열린 상태와
  좁은 창의 배치·초점·넘침을 실제 브라우저에서 확인합니다.
- `docs/`에 full 모드 UI 리뷰를 남깁니다. 범위별 근거, 변경 전후, 보존한 정보,
  검토 후 제외한 대안, 검사 결과와 미검증 범위를 기록합니다.
- 저장소 필수 게이트와 PR CI 통과 후 머지하고 사전 출시 자산까지 확인합니다.
