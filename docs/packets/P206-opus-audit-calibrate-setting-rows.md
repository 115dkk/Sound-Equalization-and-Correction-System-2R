## Steps

### 1. `settingRows.ts` and one `SettingRow`

Create `src/screens/calibrate/settingRows.ts` with the row type the ADR
gives:

```ts
type SettingRow = {
  id: string;                                  // the existing data-ui id, unchanged
  field: keyof CalibrationSettings;
  kind: SettingEdit["kind"];
  control: "toggle" | "number" | "segmented" | "select";
  limits?: keyof CalibrationLimits;
  unit?: string; step?: number; digits?: number;
  shownWhen?: (s: CalibrationSettings, view: CalibrateView) => boolean;
  disabledWhen?: (s: CalibrationSettings, view: CalibrateView) => boolean;
  hint?: (s: CalibrationSettings, view: CalibrateView) => string | null;
};
```

Fill it with every simple control `Settings.tsx` renders today (about 40;
toggles, number fields, segmented choices, selects that edit one scalar
field through one `SettingEdit` kind). The catalog keys keep their
convention (`calibrate.<section>.<name>`, `.help`, `.hint`), so a row's
label and help keys follow from its id; write them once in the table.
`shownWhen` carries ADR 0038's "not shown where it has no meaning" rules
that `Settings.tsx` has today; which card and which 고급 group a row
belongs to stays decided by the card (the card lists the row ids it shows).

Create one `SettingRow` component (next to `controls.tsx` or in it) that
renders a row with the existing kit components the cards use now (same
markup, same classes, same `data-ui` ids, same `aria` wiring), reads limits
from `CALIBRATION_LIMITS[row.limits]`, and sends `row.kind` through the
same edit path the cards use (`useCalibrateScreen`'s edit function).

Replace the hand-written simple controls in `Settings.tsx` with
`<SettingRow row={…} />` for those rows. Keep hand-written: the range card's
extra-band editor, the sub editor, the XO card and anything structured (the
ADR names them). The rendered DOM must not change: same ids, same text,
same order, same disabled and hidden states.
