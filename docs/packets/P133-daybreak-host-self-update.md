## Service: `update_self` (fixed)

1. **Key.** `const UPDATER_PUBKEY: &str` in the service equals
   `plugins.updater.pubkey` of `apps/secs2r/tauri.conf.json` (base64 of a
   minisign public key file). A unit test reads that JSON file and asserts
   equality. Decoding: base64 to text, the second line is the key for
   `minisign_verify::PublicKey::from_base64`.
2. **Manifest.** `secs2r-host.json` = `{"version": "<semver>", "sha256":
   "<64 lowercase hex>", "file": "secs2r-host.exe"}`; `secs2r-host.json.sig`
   = what `tauri signer sign` writes for that file (base64 of a minisign
   signature file; decode, then `Signature::decode`). Check the
   `tauri signer` output format in the `tauri-cli`/`tauri-bundler` sources
   if they are in the registry, otherwise from
   https://v2.tauri.app/plugin/updater/ (WebFetch) and say which.
3. **Pure rules in `rules.rs`**, unit tested with a key pair generated in
   the test (the `minisign` crate is not available; build the test
   signature with what `minisign-verify`'s own tests use, or keep a fixed
   test vector generated by `tauri signer sign` committed under
   `apps/secs2r-host/tests/data/`; say which):
   `verify_manifest(pubkey, manifest_bytes, sig_text) -> Result<HostManifest, UpdateReject>`
   and `accept_update(own: &str, manifest: &HostManifest, staged_sha256: &str) -> Result<(), UpdateReject>`.
   `UpdateReject`: `BadSignature`, `BadManifest(String)`, `NotNewer { own, offered }`,
   `HashMismatch`, `TooLarge`, `Io(String)`; each has a stable log reason.
4. **Pipe handler.** `HostRequest::UpdateSelf { from_dir }` in
   `handle_request`: `authorize_mutation(identity)` first. Read
   `<from_dir>/secs2r-host.json` and `.sig` (each at most 64 KiB), verify,
   copy `<from_dir>/<file>` (at most 64 MiB) to `secs2r-host.new.exe` in
   the service's `%ProgramFiles%` folder (the same folder the install path
   uses), hash the copy, `accept_update`. On any rejection delete the copy,
   log `update_rejected` with the reason and answer `HostResponse::Error`.
   On success log `update_staged` (version), start the copy as
   `secs2r-host.new.exe finish-update` (detached, no window, inheriting
   nothing), answer `HostResponse::Ok`, then stop the service the way an
   SCM stop does (managed CamillaDSP stops as in a normal stop; the new
   service starts it again).
5. **`finish-update` subcommand.** Waits until the service reports
   `Stopped` (poll the SCM, up to 30 s). Then renames `secs2r-host.exe` to
   `secs2r-host.old.exe` (replacing an old one), renames
   `secs2r-host.new.exe` to `secs2r-host.exe` (retry each rename for up to
   5 s while the file is still locked), starts the service, logs
   `update_done`, exits. If the service did not stop in 30 s, renames
   nothing, logs `update_timeout`, starts the service if it is stopped,
   exits. If a rename fails half way, puts the old file back before
   starting. The service deletes `secs2r-host.old.exe` at start (best
   effort, logged on failure). Keep the file operations behind a small
   trait so the order and the fallbacks are unit tested on temporary
   folders.
6. The `Core::handle` placeholder arm for `UpdateSelf` stays as the answer
   for non-Windows builds.

## Shell (fixed)

7. **Service version.** When the shell reads `HostStatus` (start, and each
   status refresh) and the service runs with a `version` lower (semver)
   than the shell's own `CARGO_PKG_VERSION`, it sends
   `UpdateSelf { from_dir: <the shell's own folder> }` once per shell
   start and per offered version, and logs the answer in its log view.
   Confirm the shell's crate version follows the workspace version (the
   release gate bumps it); if not, stop and report.
8. **App update while the app is closed.** Register `tauri-plugin-updater`
   in the shell with the same `pubkey`, endpoints and `quiet` install mode
   (add `plugins.updater` to `apps/secs2r-host-shell/tauri.conf.json`;
   `SECS2R_UPDATE_ENDPOINT` overrides the endpoints as in P132). On start
   after 60 s and every 6 h: skip when a `portable` file sits next to the
   shell, when the main app is running (existing detection), or when the
   app's stored policy is not `auto` (read `settings.updates` from the
   app's `settings.json` in `%APPDATA%\io.github.115dkk.secs2r\`; a missing
   or unreadable file means `auto`). Otherwise check; when newer, download;
   check again that the main app is not running; write `PendingUpdate` to
   `update.json` in that same app folder (atomic; `previous` from
   `raw_json["previous"]`); install quietly without relaunch. The NSIS hook
   starts the shell again after the install. If the main app started
   meanwhile, drop the bytes and leave the update to the app.
9. **Tests.** The skip rules, the policy read (missing, unreadable, each
   policy), the version comparison and the once-per-version rule, without
   network or a Tauri runtime.
