# 0013. Dirac Live 프로젝트의 측정을 가져온다

상태: 채택, 2026-10-24

## 배경

Dirac Live로 방을 보정한 사용자는 측정을 이미 `.liveproject` 파일에 갖고 있습니다. Dirac Live는 측정을 크기 응답으로만 보여 주고 IR을 내보내지 않으므로, 이 측정으로 SECS 2R을 돌리려면 REW로 처음부터 다시 재야 했습니다. 업스트림 SECS 2에는 이 기능이 없습니다.

형식은 공개되지 않았습니다. Dirac Live 3.14.3이 만든 표본 프로젝트 11개를 살펴본 결과는 [`docs/DIRAC_LIVEPROJECT.md`](../DIRAC_LIVEPROJECT.md)에 있습니다. 요점은 셋입니다.

- 파일은 Qt `QDataStream`이고, 그 안의 측정 세션은 암호화되지 않은 protobuf입니다. 필터 설계로 보이는 덩어리만 암호화돼 있습니다.
- 측정 세션에 위치마다, 채널마다 IR(32769표본, μ-law 16비트)이 있습니다. 녹음에서 다시 만든 IR과 레벨 비가 0.05 dB 안에서 맞고, 마이크 보정이 들어 있으며, 한 위치 안에서는 채널 사이의 도착 시각 차이가 남습니다.
- 같은 세션에 위치마다의 녹음(Ogg Vorbis)도 있습니다.

## 결정

- **저장된 IR을 읽습니다.** Dirac 자신이 분석한 값이고(마이크 보정, 클럭 차이 보정 포함), 표본 프로젝트에서는 저장된 구간 밖에 쓸 만한 신호가 없었습니다. 녹음을 디컨볼루션하는 길은 Vorbis 디코더와 Dirac 스윕의 복원을 들여야 하므로 택하지 않습니다.
- **암호화된 부분은 건드리지 않습니다.** 필터 설계, 계정 정보, 프로세서 상태는 읽지 않습니다. 헤더의 사용자 ID와 보정 파일 경로도 화면이나 프로젝트에 옮기지 않습니다.
- **새 크레이트 `secs-dirac`가 형식을 맡습니다.** 신뢰할 수 없는 파일을 읽으므로 `secs-mdat`처럼 `#![forbid(unsafe_code)]`, 할당 상한(`Limits`), Miri와 fuzz 대상을 둡니다. 외부 의존성은 `thiserror`뿐이고 protobuf는 필요한 필드만 직접 읽습니다. 의존 방향은 `secs-service → secs-dirac`입니다.
- **mdat 가져오기 흐름에 얹습니다.** 화면은 이미 측정 행마다 위치와 채널을 고르는 대화상자를 갖고 있습니다. 서비스가 경로의 확장자로 형식을 고르고, IPC(`mdat_scan`, `mdat_import`, `dialog_pick_mdat`)와 바인딩은 그대로 씁니다. 파일 선택 대화상자는 두 형식을 함께 받습니다.
- **가져오기 규약.** 모든 IR의 `t0`는 −0.25 s, Dirac 위치 p(0부터)는 SECS 2R 위치 p + 1, 역할은 Dirac 채널 이름에서 제안하고 서브우퍼는 순서대로 SW1부터 제안합니다. 마이크 보정은 IR에서 빼지 않습니다. 빼려면 Dirac이 보정을 건 방식(위상 포함)을 알아야 하는데, 그것은 형식에서 드러나지 않습니다.
- **새 기능 표시.** `features.toml`에 `format.dirac_liveproject_read`와 `measure.dirac_import`를 `upstream = "new"`로 등록합니다.

## 결과

- Dirac Live로 측정한 사용자가 다시 측정하지 않고 같은 측정으로 SECS 2R을 돌리고, 두 보정을 같은 측정에서 비교할 수 있습니다.
- Dirac에서 가져온 IR만 마이크 보정이 들어간 값입니다. 보정 파일이 고역에서 크게 꺾이는 마이크라면 REW 측정과 섞어 쓸 때 고역 레벨이 어긋납니다. 형식 문서와 기능 메모에 적습니다.
- 위치 사이의 절대 지연은 알 수 없습니다. REW를 음향 타이밍 기준 없이 쓴 경우와 같은 처지이고, 엔진의 시간 축 규약은 기준 위치의 가장 이른 도착을 0으로 두므로 계산은 그대로 돕니다.
- Dirac이 형식을 바꾸면 읽기가 실패할 수 있습니다. 실패는 오류로 끝나고 측정 저장소는 바뀌지 않습니다. 다른 판의 표본을 얻으면 형식 문서와 테스트를 고칩니다.
