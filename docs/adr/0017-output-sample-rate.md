# 0017. 출력 샘플레이트

상태: 채택, 2026-10-28

## 배경

SECS 2R은 측정, 설계, 내보내기를 모두 48 kHz로 합니다(`secs-graph::SAMPLE_RATE`). 48 kHz가 아닌 측정은 `SampleRatePolicy`로 거부하거나, 계산용 IR만 48 kHz로 바꿔 씁니다. 내보낸 FIR WAV와 계수, 딜레이 샘플 수, CamillaDSP의 `samplerate`, EqAPO 안내도 모두 48 kHz를 전제합니다.

출력 장치가 다른 레이트로 도는 경우가 있습니다. 44.1 kHz 계열 음원을 그대로 재생하는 PC 컨볼버, 96 kHz로만 도는 DSP가 그렇습니다. miniDSP Flex와 2x4 HD는 96 kHz로 돌고, FIR은 출력 하나에 최대 2048탭, 합계 4096탭입니다([miniDSP Flex 설명서, FIR filtering](https://docs.minidsp.com/product-manuals/flex/dsp-reference/fir-filtering.html)). 지금의 `minidsp` 프리셋은 이 탭 수를 48 kHz로 보고 43 ms 길이의 필터를 설계한 뒤 48 kHz 계수를 냅니다. 이 계수를 96 kHz 장치에 넣으면 필터의 주파수가 두 배로 옮겨 갑니다. 업스트림도 같습니다.

유지보수자는 출력 레이트를 지원하되 기본값은 48 kHz로 두기로 했습니다(2026-10-28).

## 결정

- **측정과 설계는 48 kHz에 둡니다.** 보정이 다루는 대역은 20 kHz 아래이고, 48 kHz 측정은 24 kHz까지 담습니다. 그래서 측정을 출력 레이트로 할 까닭이 없습니다. 입력은 지금처럼 `SampleRatePolicy`로 받고, 측정 레이트로 직접 계산하는 방식은 두지 않습니다. 오라클과 골든은 48 kHz 그대로입니다.
- **출력 레이트는 DSP 프로파일의 값입니다.** `DspProfile.output_rate`는 44100, 48000, 88200, 96000, 176400, 192000 가운데 하나이거나 '자동'입니다. 프리셋 값은 `camilla` 48000, `tesira` 48000, `qsys` 48000, `minidsp` 96000, `custom` 48000입니다. `minidsp`, `tesira`, `qsys`는 장치가 정한 값이라 화면에서 바꾸지 않고, `camilla`와 `custom`은 바꿀 수 있습니다. 값이 없는 옛 프로젝트는 프리셋의 값을 씁니다. 설계는 48 kHz에서 하므로 출력 레이트는 계산 결과에 들어가지 않고, 바꿔도 결과는 낡지 않습니다. 내보낼 때 그 시점의 출력 레이트로 옮깁니다.
- **필터의 시간 길이는 보정 모드가 정합니다.** 엔진은 지금처럼 보정 모드가 정한 48 kHz 탭 수(혼합과 선형 2048, 울트라 최대 16384)로 설계하고, DSP 프로파일의 탭 수는 읽지 않습니다. 업스트림도 같습니다. 내보낼 때 FIR은 같은 시간 길이로 출력 레이트에 옮기므로, 탭 수는 `48 kHz 탭 × 출력 레이트 / 48000`을 반올림한 값이 됩니다. 출력 레이트가 48 kHz이면 지금과 같습니다.
- **DSP 프로파일의 탭 수와 예산은 출력 레이트의 탭입니다.** 화면은 채널 FIR과 MIMO FIR 합계를 출력 레이트의 탭으로 바꿔 프로파일의 탭 수, 예산과 견주고, 넘으면 알립니다. 설계 길이를 프로파일에 맞춰 줄이는 기능은 이 ADR에 넣지 않습니다.
- **필터를 옮기는 규칙.**
  - PEQ, 크로스오버, 올패스 같은 IIR은 같은 주파수, Q, 이득으로 출력 레이트에서 다시 만듭니다(RBJ).
  - 딜레이는 출력 레이트의 샘플 수로 반올림합니다(짝수 쪽 반올림).
  - FIR은 48 kHz 설계의 응답을 출력 레이트의 주파수 격자에서 다시 표본화해 만듭니다. 20 kHz 아래는 원래 응답을 그대로 따릅니다. 그 위는 20 kHz의 크기를 가진 순수 딜레이로 잇는데, 딜레이는 48 kHz FIR에서 절댓값이 가장 큰 탭의 시각(포물선 보간)이고, 20 kHz에서 23 kHz(출력 레이트의 나이퀴스트가 더 낮으면 그곳)까지 raised-cosine으로 원래 응답에서 넘어갑니다. 길이는 위의 탭 수로 자르고 윈도는 다시 걸지 않습니다. 48 kHz 설계에 이미 `rc::truncate`의 끝 윈도가 들어 있어, 한 번 더 걸면 저역이 바뀝니다.
  - 컨볼루션 IR은 위 규칙으로 옮긴 필터를 출력 레이트에서 다시 렌더링합니다.
  - 저율 FIR(MIMO 서포트)은 설계 레이트에서 출력 레이트로 바로 펼칩니다.
  - 엔진이 설계하는 FIR(2048탭 이상)을 쓰는 사슬에서, 옮긴 필터와 48 kHz 필터의 응답은 딜레이를 뺀 사슬로 견줍니다. 수 탭짜리 FIR은 같은 시간 길이로는 다른 레이트에서 응답을 지킬 수 없고, 엔진은 그런 FIR을 만들지 않습니다. 20 kHz 아래의 주파수 가운데 사슬 전체의 응답이 최대값의 −30 dB 안인 곳에서는 0.1 dB와 1도 안에서 같고, 그보다 낮은 곳에서는 두 응답의 차이가 최대값보다 50 dB 이상 작아야 합니다. 딜레이는 레이트마다 그 레이트의 샘플로 반올림하므로 최대 반 샘플(44.1 kHz에서 11.3 µs)씩 어긋나고, 이것은 48 kHz 내보내기가 지금도 가진 반올림과 같은 종류입니다. 테스트가 두 가지를 따로 확인합니다.
- **예측과 성적표는 48 kHz 설계로 계산합니다.** 옮긴 필터와의 차이는 위 허용오차 안에 있으므로 따로 계산하지 않습니다.
- **내보내기는 출력 레이트를 따릅니다.** CamillaDSP의 `samplerate`, EqAPO 안내의 장치 형식, 필터 값 텍스트의 딜레이, FIR WAV와 계수가 출력 레이트로 나가고, 설계 정보 파일(`secs-design.json`)과 안내 파일에 레이트를 적습니다. 컨볼루션 IR은 출력 레이트 하나를 기본으로 쓰고, 재생 레이트마다 필터를 고르는 컨볼버를 위해 다른 레이트를 함께 고를 수 있습니다. REW mdat은 측정과 계산 응답을 담으므로 48 kHz 그대로입니다.
- **'자동'은 PC 프로파일(`camilla`, `custom`)에서만 고릅니다.** 내보낼 때 장치의 레이트를 읽어 정하고, 정한 값을 `secs-design.json`과 안내 파일에 적습니다. 기본 재생 장치의 공유 모드 레이트를 읽고, 실행 중인 CamillaDSP에 적용하는 구성(ADR 0018)이 들어오면 그 설정의 `samplerate`를 읽습니다. 읽지 못하거나 위 여섯 값이 아니면 48 kHz로 내보내고 그 사실을 알립니다.

## 결과

- 출력 레이트가 48 kHz이면 설계와 내보낸 바이트가 지금과 같고, 골든은 바뀌지 않습니다.
- `minidsp` 프리셋은 96 kHz 계수를 냅니다. 이 프리셋을 쓰는 옛 프로젝트도 다시 계산할 필요 없이, 다시 내보내면 96 kHz 계수가 나갑니다. 혼합 모드의 2048탭 설계는 96 kHz에서 4096탭이 되어 miniDSP의 출력당 2048탭을 넘고, 화면이 이것을 알립니다. 업스트림은 48 kHz 계수 2048탭을 그대로 내므로, 편차로 적습니다.
- 44.1 kHz 계열 출력에서는 22.05–24 kHz 대역의 보정이 빠집니다. 보정이 다루지 않는 대역입니다.
- 출력 레이트를 바꿔도 다시 계산하지 않고 다시 내보내기만 하면 됩니다. 재생 레이트마다 필터를 고르는 컨볼버에는 컨볼루션 IR의 추가 레이트를 고르면 한 번에 여러 레이트의 IR이 나갑니다.
