# 0008. 큰 MIMO 선형계를 f64 GPU로 풀고 장치에 따라 자동 선택한다

상태: 채택, 2026-10-19

## 배경

유지보수자는 실제 GPU 가속 시스템과 CLI·UI 선택을 요청했습니다. 내장,
지나치게 오래되거나 느린 GPU, 지원하지 않는 장치는 CPU를 기본으로 하고,
그 밖의 지원되는 GPU는 기본으로 사용합니다. 직접 고른 CPU/GPU 설정은
자동 선택과 구분해 보존합니다.

2026-10-19 실측에서 IIR 입력 하나의 응답·미분·시간열 FFT·잔차는 약 19%,
정규 방정식까지 포함한 목적함수는 55.6%였습니다. 반면 선행 이상 FIR의
2160차 선형계와 19회 적응형 λ 탐색은 같은 입력에서 CPU 중앙값 1.226초,
CUDA f64 0.252초였습니다. 19개 분기와 선택 λ가 일치했고, 선택 서포트 에너지
비율의 절대 차이는 4.05e-11이었습니다. f32는 큰 해 오차와 분해 실패를
보였습니다. 따라서 0007의 초기 IIR 잔차 전용 wgpu 계획을 이 결정으로
대체합니다. 전체 앱이 4.86배 빨라진다는 뜻은 아닙니다.

## 결정

- 첫 가속 단계는 MIMO의 **이상 FIR 정칙화 탐색**입니다. 행렬과 계산은 f64로
  유지하고 GPU 고유분해를 한 번 재사용해 대각 이동 문제를 풉니다. λ 선택,
  서포트 레벨 판정, 가드와 IIR 실현은 기존 CPU 방법을 유지합니다.
- 끝단 검증에 따른 출하 범위는 **FIR 모드**입니다. 세 방 샘플의 IIR 모드에서
  1.1e-8 이하의 이상 목표 상대 차이가 최종 SPL 최대 0.557–3.351 dB 차이와
  경로 선택 차이로 증폭됐습니다. IIR 모드는 목표 설계부터 CPU 기준을 유지하고
  `iir_reference` 사유를 기록합니다. 허용오차를 늘려 이 경로를 출하하지 않습니다.
- 엔진의 실제 seam은 `RidgeBackend`/`ShiftedSystem`입니다. 기준 CPU
  어댑터는 기존 `RidgeSweep`를 사용합니다. GPU가 없는 기존 엔진 진입점은
  CPU를 유지하여 결정성·오라클 테스트를 바꾸지 않습니다.
- `secs-gpu`가 장치 정책과 CUDA 어댑터를 소유합니다. 네이티브 로더·포인터·
  CUDA/cuBLAS/cuSOLVER 호출은 새 격리 크레이트 `secs-cuda-sys`에만 둡니다.
  이 크레이트는 `secs-gpu`만 의존할 수 있습니다. 기존 OS 격리인
  `secs-sys`의 앱 전용 규칙은 유지합니다.
- 새 격리 크레이트의 초기 handwritten unsafe 상한은 80토큰입니다. 실제
  수와 경계 의무를 검토해 기록합니다. 나머지 크레이트 예산은 0입니다.
  공개 API에는 소유 값, 검사된 슬라이스, 열거형, Result만 두고 원시 핸들,
  포인터, unsafe fn/trait, 수동 Send/Sync를 노출하지 않습니다. 네이티브
  계산 객체는 생성된 작업 스레드 안에서만 사용합니다.
- 네이티브 라이브러리는 선택적 런타임 의존성으로 동적 로드합니다.
  SDK가 없는 호스트도 정상 기동하며, 로드 실패·미지원 플랫폼을 상태로
  반환합니다. 사용자 지정 라이브러리 디렉터리와 설치 방법은 문서화하고,
  누락된 런타임을 사용 가능한 GPU로 표시하지 않습니다. Python/CuPy나
  외부 자식 프로세스는 출하 경로에 필요하지 않습니다.
- 자동 선택은 사용 가능한 런타임과 실제 장치 속성을 확인합니다. 내장
  GPU, 지원 세대 미만, 메모리·연산 자원이 부족한 장치는 CPU입니다.
  적격 장치가 여러 개면 안정적인 성능 순위로 하나를 고릅니다. 세대·
  자원 경계와 사유는 테스트 가능한 값으로 명시합니다.
- 자동/GPU 선택 상태와 실제 실행 결과를 구분합니다. 작은 문제는 CPU가
  더 빠를 수 있으므로 자동 모드에는 크기 기준을 둡니다. 명시적 GPU는
  지원되는 장치에서 그 크기 기준을 재정의할 수 있습니다. 사용할 GPU가
  없는 명시적 GPU 요청은 명확한 오류로 응답합니다.
- 하나의 장치 사용권은 factor부터 모든 shifted solve가 끝날 때까지
  유지합니다. 대기는 취소 가능하고 메모리 예산을 검사합니다. GPU 오류,
  메모리 부족 또는 비정상 수치가 발생하면 그 입력의 λ 탐색 전체를 CPU로
  다시 실행합니다. 취소는 fallback하지 않고 종료합니다.
- 선택은 앱 로컬 설정(`auto/cpu/gpu`)이며 업스트림 `.secs` 파일에
  새 하드웨어 설정을 쓰지 않습니다. CLI와 UI가 같은 정책·상태 API를
  사용합니다. 저장된 CPU 선택을 하드웨어 자동 감지로 덮어쓰지 않습니다.
- 결과와 내보내기에는 실제 가속 단계·장치·CPU/GPU 처리 수·fallback을
  기록합니다. 선택 변경은 캐시/낡음 판정에 반영해 다른 계산 경로의
  결과를 새로 실행한 것처럼 재사용하지 않습니다.

## 검증과 출하

CPU의 결정성·골든은 그대로 유지합니다. 가짜 장치로 장치 정책,
지원 없음, 오래된 설정 이주, 명시적 선택, 취소 및 CPU fallback을 CI에서
검사합니다. 실제 GPU에서는 같은 행렬의 해·λ 궤적·서포트 에너지와 끝단
음향 지표를 대조하고 release 성능을 기록합니다. 성능 판정은 가속 단계
범위를 명시하며 0007의 3배 목표를 새 이상 FIR sweep에서 확인합니다.
UI는 설치된 make-interfaces-feel-better 규칙과 기존 CSS·ko/en 카탈로그를
따릅니다. 지원하지 않는 장치의 CPU 기본값도 정상 흐름으로 검증합니다.
