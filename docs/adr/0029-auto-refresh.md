# 0029. 낡은 결과 자동 갱신

상태: 채택, 2026-10-31

## 배경

보정 설정을 바꾸면 결과는 '보정 필요'로 표시되고, 사용자가 '다시 보정하기'를 눌러야 새 결과가 나옵니다. 0.41.0 사용자는 값을 바꾸자마자 영향을 받는 수치가 모두 자동으로 다시 계산되기를 바랐습니다(2026-10-31). 유지보수자는 앱 설정에 '추천값 등이 낡았을 때 자동으로 최신으로 갱신'을 두되 기본은 꺼짐으로 하고, 예상하지 못한 자원 소모가 없도록 자동 계산은 자원을 절반까지만 쓰게 하기로 했습니다.

## 결정

### 설정

- 앱 설정(`AppSettings`)에 `auto_refresh`(기본 꺼짐)를 추가합니다. 프로젝트가 아니라 이 컴퓨터의 앱에 속하는 선택입니다.
- 화면의 이름은 '낡은 결과 자동 갱신'이고, 도움말(i)에 무엇을 다시 계산하는지와 함께 '주의: 설정을 바꿀 때마다 다시 계산하므로 팬 소음이 커지기도 합니다.'를 둡니다.

### 다시 계산하는 때와 대상

- 켜져 있으면, 보정 결과가 낡았고(설정, 타겟, 측정이 바뀜) 실행 중인 작업이 없을 때 마지막 변경에서 1.5초가 지나면 자동 갱신을 시작합니다. 대상은 사용자가 '보정 계산'을 눌렀을 때와 같습니다. 'XO 추천 포함'(0028)이 켜져 있으면 XO 추천부터, 'MIMO 함께 계산'이 켜져 있으면 MIMO까지 계산합니다.
- 자동 갱신 중에 설정이 또 바뀌면 그 작업을 취소하고, 다시 1.5초를 기다린 뒤 새로 시작합니다. 사용자가 직접 시작한 작업은 취소하지 않고, 그 작업이 끝난 뒤 낡았으면 그때 시작합니다.
- 측정, 내보내기, DSP 적용은 자동으로 하지 않습니다. 자동 갱신은 결과를 다시 계산할 뿐이고, 장치에 적용하는 일은 사용자가 합니다.

### 자원

- 자동 갱신 작업은 요청에 `background: true`를 실어 보내고, 서비스는 이 작업의 계산 컨텍스트를 줄여 만듭니다.
  - CPU가 둘 이상이면 스레드 수를 CPU 수의 절반(내림, 최소 1)으로 합니다.
  - CPU가 하나면 계산과 휴식을 번갈아 사용률을 절반으로 묶습니다. 취소 토큰을 확인할 때마다, 마지막 휴식 뒤 50 ms 이상 계산했으면 같은 시간만큼 쉽니다. 엔진은 맞춤과 단계 경계에서 이 토큰을 자주 확인하므로 휴식이 고르게 들어갑니다.
- 메모리 예산은 지금과 같습니다. MIMO의 GPU 사용은 바꾸지 않습니다.
- 사용자가 직접 누른 계산은 지금처럼 모든 CPU를 씁니다.

## 결과

- 켜면 설정을 바꾸고 잠시 뒤 결과가 저절로 최신이 됩니다. 계산 시간은 자원을 절반만 쓰므로 직접 누를 때보다 깁니다.
- 끄면(기본) 지금과 같습니다.
- 계산 결과는 스레드 수와 휴식에 따라 바뀌지 않습니다(ADR 0007의 map만 쓰는 병렬).
