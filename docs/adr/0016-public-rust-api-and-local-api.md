# 0016. 공개 Rust API와 로컬 API

상태: 채택, 2026-10-28

## 배경

SECS 2R의 계산과 내보내기는 `secs-service`의 `Service` 하나로 들어갑니다. 화면과 CLI는 같은 요청(`secs-types::ipc::Request`)으로 이것을 부릅니다. 바깥 프로그램이 이 기능을 쓸 수 있는 곳은 CLI뿐이었습니다.

2026-10-28에 두 요청이 겹쳐 들어왔습니다. 외부 테스터는 실행 중인 앱의 상태를 읽고 조작할 127.0.0.1 HTTP·WebSocket 입구를 원했습니다. 그의 감시 프로그램이 Dirac Live Processor의 로컬 REST API를 몇 초마다 읽는 것과 같은 용도입니다. 유지보수자는 같은 기능을 crates.io에 Rust 라이브러리로 공개하기로 했습니다.

crates.io에 올리는 크레이트는 crates.io에 있는 크레이트만 의존할 수 있습니다. 경로 의존성은 개발 의존성일 때만 게시하면서 지워집니다. 그래서 계산 엔진을 공개하려면 `secs-service`와 그 아래 크레이트를 함께 올려야 합니다.

## 결정

- **공개 크레이트는 `sound-equalization-and-correction-system-rust-api` 하나입니다.** 디렉터리는 `crates/secs-api`이고 라이브러리 이름은 패키지 이름을 따릅니다. 기능(feature)은 둘입니다. `engine`(기본)은 앱 없이 파일만으로 프로젝트를 열고, 측정을 가져와 보정과 MIMO를 계산하고, 내보내는 `Engine`입니다. `client`는 실행 중인 앱의 로컬 API를 부르는 `Client`입니다. 둘은 같은 요청 타입을 받는 트레이트 하나를 구현하므로, 호출하는 코드는 어느 쪽을 쓰든 같습니다. 요청과 응답 타입은 `secs-types`를 그대로 다시 내보냅니다.
- **내부 크레이트도 지금 이름으로 함께 올립니다(유지보수자 결정 2026-10-28).** 올리는 크레이트는 `secs-types`, `secs-dsp`, `secs-compute`, `secs-engine`, `secs-jos`, `secs-mdat`, `secs-project`, `secs-dirac`, `secs-export`, `secs-graph`, `secs-camilla`, `secs-filters`, `secs-rew`, `secs-audio`, `secs-service`입니다. 판 호환을 약속하는 것은 공개 크레이트 하나뿐이고, 내부 크레이트의 설명과 README에 그렇게 적습니다. 공개 크레이트는 내부 크레이트를 같은 판으로 정확히 고정(`=X.Y.Z`)해 의존합니다. `secs-sys`, `secs-gpu`, `secs-cuda-sys`, `secs-oracle`, `secs-policy`와 앱은 올리지 않습니다. 그래서 공개 API에는 운영체제 오디오 장치로 하는 자체 측정과 GPU 가속이 없습니다. 오디오 백엔드는 `secs-audio`의 seam으로 사용자가 넣을 수 있습니다.
- **라이브러리 판은 앱 판과 따로 갑니다.** 게시하는 크레이트 16개는 한 판을 함께 쓰고 0.1.0에서 시작합니다. 앱과 게시하지 않는 크레이트는 지금처럼 작업 공간 판(0.30.x)을 씁니다. 화면과 내보낸 파일에 적는 'SECS 2R 판'은 앱이 `Deps`로 넘긴 앱 판입니다. `Engine`이 만든 서비스는 라이브러리 판을 적습니다.
- **게시한 파일만으로 빌드됩니다.** 게시 크레이트는 자기 디렉터리 밖의 파일을 읽지 않습니다. `UPSTREAM.toml`과 업스트림 mdat 서식 파일처럼 밖에서 읽던 것은 크레이트 안에 사본을 두고, 원본과 같은지 정책 검사가 확인합니다. GPL-3.0 전문(`LICENSE`)도 크레이트마다 사본을 둡니다. 게시하는 기능은 게시하지 않는 크레이트를 의존하지 않습니다. 패키지에는 `src`, 빌드 스크립트, `README.md`, `LICENSE`만 넣고 테스트와 골든, 예제는 넣지 않습니다. CI는 `cargo publish --workspace --dry-run`으로 이 조건을 확인합니다.
- **첫 게시(0.1.0)는 임시 토큰으로 하고, 그다음은 trusted publishing으로 합니다.** 유지보수자가 준 일주일짜리 토큰으로 0.1.0을 올린 뒤, 크레이트마다 GitHub trusted publisher(이 저장소, `release.yml`, 환경 `crates-io`)를 등록합니다. 그 뒤로는 `release.yml`이 OIDC로 받은 단기 토큰으로 게시하고, 저장소에는 crates.io 토큰을 두지 않습니다. 판은 게시 크레이트의 패키지 파일이 지난 라이브러리 태그(`api-vX.Y.Z`) 뒤로 바뀐 릴리스에서만 올립니다. 그 파일을 바꾼 커밋 가운데 `feat`이나 호환이 깨지는 변경 표시(`!`, `BREAKING CHANGE`)가 있으면 minor를, 없으면 patch를 올립니다. 0.x에서 minor는 호환이 깨질 수 있는 판이므로, 새 기능은 모두 호환이 깨진다고 보고 올리는 셈입니다.
- **로컬 API는 앱 안의 HTTP 서버입니다.** 새 크레이트 `secs-local-api`가 서버를 맡고(게시하지 않음, `#![forbid(unsafe_code)]`), 앱이 서비스를 넘겨 띄웁니다. 앱 설정에서 켜야 열리고 기본값은 꺼짐입니다. 127.0.0.1에만 묶고, 포트는 기본 4712이며 설정에서 바꿉니다. 입구는 셋입니다.
  - `POST /v1/call`은 화면의 `secs_call`과 같은 요청 JSON을 받아 같은 봉투를 돌려줍니다.
  - `GET /v1/status`는 앱 판, 열린 프로젝트, 실행 중인 작업, 최신 성적표(MIMO 포함)와 낡음 표시, 마지막 내보내기(종류, 설계 이름, 폴더, 시각)를 한 번에 돌려줍니다. 감시 프로그램이 몇 초마다 부르는 용도입니다.
  - `GET /v1/events`는 WebSocket입니다. 화면에서 시작했든 API에서 시작했든 모든 작업 이벤트와, 상태를 바꾼 요청의 알림을 보냅니다.

  응답 모양과 경로는 `secs-types`에 두어 서버와 `Client`가 같은 정의를 씁니다.
- **로컬 API는 토큰을 요구합니다.** 127.0.0.1에만 열어도 브라우저의 웹 페이지가 그 주소로 요청을 보낼 수 있기 때문입니다. 앱 설정 폴더의 `local-api-token`에 무작위 256비트 토큰을 두고, 모든 요청에 `Authorization: Bearer`를 요구합니다. `Host`가 `127.0.0.1:<포트>`나 `localhost:<포트>`가 아니거나 `Origin` 헤더가 붙은 요청은 거부합니다. 요청 본문은 1 MiB까지 받습니다. 본문을 받는 도중 2초 동안 새 바이트가 오지 않으면 408로 끝내고, 바이트가 계속 오면 전체 시간이 2초를 넘어도 기다립니다. 그래서 본문을 보내다 멈춘 연결이 있어도 앱을 닫을 때 서버가 멈춥니다(감사 #155 TD-126). 토큰은 설정 화면에서 복사하거나 새로 만듭니다.
- **API로 부를 수 없는 요청이 있습니다.** 파일 대화상자, 폴더 열기, 도움말 열기처럼 사용자 화면에 창을 띄우는 요청은 거부합니다. 요청마다 '화면 전용'인지와 '상태를 바꾸는지'를 `secs-types`의 표 하나에 적고, 모든 요청이 표에 있는지 테스트가 확인합니다.
- **화면은 바깥에서 바뀐 상태를 따라갑니다.** 서비스는 모든 작업 이벤트를 받는 관찰자 하나를 `Deps`로 받습니다. 로컬 API가 상태를 바꾸는 요청을 처리하면 앱이 화면에 알림 이벤트를 보내고, 화면은 관련 상태를 다시 읽습니다. 서비스는 마지막 내보내기를 기억합니다.

## 결과

- Rust 프로그램은 `cargo add sound-equalization-and-correction-system-rust-api --rename secs`로 엔진을 넣거나 실행 중인 앱을 부릅니다. 다른 언어로 쓴 프로그램은 로컬 API를 HTTP로 부릅니다.
- 내부 크레이트 15개의 이름을 crates.io에서 계속 점유합니다. 내부 크레이트의 공개 항목은 판을 올릴 때 호환 없이 바뀌기도 합니다.
- 게시하는 크레이트마다 `LICENSE` 사본이 생기고, `secs-service`와 `secs-mdat`에는 원본 사본(`UPSTREAM.toml`, 업스트림 mdat 서식)이 생깁니다. 정책 검사가 원본과 같은지 지키므로, 업스트림을 병합할 때 사본도 함께 바꿔야 합니다.
- 로컬 API를 켜면, 토큰을 읽을 수 있는 같은 PC의 프로그램은 프로젝트를 열고 계산을 돌리고 파일을 쓸 수 있습니다. 토큰 파일은 사용자 설정 폴더에 있으므로 같은 사용자의 프로그램만 읽습니다. 측정 요청은 스피커로 스윕을 냅니다.
- ADR 0003의 'IPC는 커맨드 하나'는 화면에 그대로 적용됩니다. 로컬 API는 같은 요청을 다른 입구로 받을 뿐이고, 화면의 CSP는 바뀌지 않습니다.
