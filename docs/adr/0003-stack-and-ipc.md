# 0003. 러스트 코어, Tauri 2 셸, React와 TypeScript 화면, 타입 있는 IPC 하나

상태: 채택, 2026-10-13

## 배경

업스트림은 파이썬(numpy, scipy)과 PyQt6이고 Windows에서만 PyInstaller로 묶어 냅니다. 보정 계산 한 번에 수십 초, MIMO 계산에 십 분 넘게 걸리고, 화면은 옵션이 많아 혼란스럽다는 사용자 평이 이미 있습니다. 사용자 평의 원인은 옵션 수가 아니라 배치입니다. 같은 무게로 늘어놓은 입력칸, 두세 곳에 겹친 설정, 엔진이 읽지 않는 칸이 섞여 있습니다.

## 결정

- **코어는 러스트입니다.** 에디션 2024, 툴체인은 `rust-toolchain.toml`로 고정합니다. DSP는 f64이고 NumPy·SciPy의 의미를 함수 단위로 맞춥니다(0004). FFT는 realfft, 선형대수는 faer(`std` 끔), 병렬은 rayon, SIMD는 pulp입니다.
- **셸은 Tauri 2이고, 화면은 처음부터 새로 짭니다.** React 19, TypeScript(strict), Vite를 씁니다. 스타일은 CSS 토큰과 일반 CSS 하나로 하고 두 번째 스타일 체계를 들이지 않습니다. 그래프는 uPlot(로그 주파수 축, 수천 점 곡선 수십 개)이고 배치도는 직접 그린 SVG입니다. 업스트림 화면 코드는 옮기지 않고, 기능 목록과 사용자 피드백만 가져옵니다.
- **화면 리뷰 기준은 make-interfaces-feel-better입니다.** 문장은 합니다체, 상태와 라벨은 명사구로 씁니다. 라벨은 동작 방식이 아니라 효과를 말하고, 옵션은 번호가 아니라 이름으로 부릅니다. 화면마다 채운 기본 동작은 하나이고 강조색도 하나입니다. UI 글자는 14px, 캡션은 13px 아래로 내리지 않습니다. 바뀌는 숫자에는 tabular-nums를 씁니다. 오류 문구에는 원인과 다음 행동을 적고 원문은 '자세히'에 둡니다. 긴 계산은 화면을 막지 않고, 취소하면 실제로 멈춥니다.
- **IPC는 커맨드 하나입니다.** 화면은 `secs_call`에 `{method, params}` 요청을 보내고, 언제나 봉투 `{ok: true, data}` 또는 `{ok: false, error}`를 받습니다. 커맨드는 거부(reject)하지 않습니다. 요청과 응답 타입은 `secs-types`에 있고, ts-rs가 `apps/secs2r/ui/src/ipc/bindings/`에 TypeScript 타입을 생성합니다. CI는 바인딩을 다시 생성해 저장소 사본과 다르면 실패합니다. 손으로 쓰는 IPC 타입은 봉투의 합집합 하나뿐이고, 그 모양은 러스트 테스트(`envelope_wire_shape`)가 고정합니다.
- **긴 작업의 진행은 밀어 보냅니다.** M4부터 잡을 시작하는 요청은 Tauri `Channel`을 함께 받아 진행, 로그, 완료를 그 채널로 보냅니다. 화면은 폴링하지 않습니다.
- **서비스가 깊은 모듈입니다.** `secs-service`의 인터페이스는 `call(Request) -> Envelope`와 잡 이벤트 둘이고, 프로젝트 세션, 잡 레지스트리, 단계 캐시, 결과 낡음 판정, 내보내기 조립을 안쪽에 둡니다. Tauri 앱과 CLI(`secs2r-cli`)는 이 위의 얇은 어댑터이고, 테스트는 Tauri 없이 서비스를 직접 부릅니다.
- **오류와 문구는 코드로 오갑니다.** 엔진과 서비스는 문장이 아니라 코드와 인자를 돌려주고, 화면이 지금 언어로 문장을 만듭니다. 카탈로그는 언어마다 하나이고 키 집합과 자리표시자가 같아야 합니다(화면 테스트가 확인). 한국어가 원문이고 영어를 처음부터 함께 냅니다.
- **CSP를 실제로 겁니다.** `script-src 'self'`, `connect-src`는 IPC만 허용합니다. 글꼴과 그림은 앱에 묶어 넣고 외부에서 받지 않습니다.

## 결과

- 화면과 서비스가 같은 타입 정의를 쓰므로 한쪽만 바꾸면 컴파일이나 CI에서 걸립니다.
- 서비스가 Tauri를 모르므로 CLI, 통합 테스트, 성능 감사가 화면 없이 같은 경로를 돕니다.
- React와 Vite는 npm 의존성 변화가 잦습니다. 버전은 `package.json`에 정확히 고정하고 `package-lock.json`으로 잠급니다. CI는 Node 24(npm 11)로 돕니다. npm 10에는 이 의존성 묶음에서 실패하는 피어 해석 결함이 있습니다.
