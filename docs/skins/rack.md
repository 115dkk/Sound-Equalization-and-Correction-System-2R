# Hardware Rack (`rack`) 디자인 헌법

> **앰프 페이스플레이트.** 19인치 랙에 볼트로 고정된 하드웨어. 화면이 아니라 손에 닿을 듯한 기계여야 합니다.

EqualizerAPO-XT의 [`docs/skins/rack.md`](https://github.com/115dkk/EqualizerAPO-XT/blob/main/docs/skins/rack.md)를 SECS 2R의 재료(React, CSS 커스텀 프로퍼티)로 옮긴 헌법입니다. Qt의 QPainter 조문은 그라디언트와 의사 요소의 조문이 되었습니다.

## 철학

Hardware Rack은 세 스킨 중 유일한 정직한 스큐어모피즘입니다. 모든 카드가 랙 유닛이고 모든 컨트롤이 물리 부품입니다(브러시드 메탈 페이스플레이트, 네 귀퉁이의 일자 나사, 상태 LED, 함몰된 LCD 판독창, 기계 가공 캡). 이 스킨이 사용자에게 주는 약속은 "이 장비는 만질 수 있을 것처럼 생겼고, 실제 하드웨어처럼 행동한다"입니다.

모든 스트로크의 공식 타이브레이커는 한 질문입니다. **"이것이 하드웨어 페이스플레이트에 있을 물건인가?"** 나사, 홈, LED, 각인 인쇄는 '예'입니다. 글로우, 값 호, 추상 장식은 '아니오'입니다. 예외는 둘뿐입니다. 얇은 키보드 초점 링과 호버 하이라이트는 UI에 꼭 필요해서 남기되, 의도적으로 작게 유지합니다.

## 불변 규칙

아래 조항은 모든 구성 요소가 공유하므로, 구성 요소 절은 조항 이름(표시창 조항, LED 문법, 전원 내림 등)으로만 가리키고 되풀이하지 않습니다.

1. **CSS로만 그리고, 이미지 금지.** 나사·결·명판·LED 전부 그라디언트(`linear-gradient`, `radial-gradient`, `repeating-linear-gradient`)와 `box-shadow`, 의사 요소로 그립니다. 비트맵이나 SVG 에셋이 들어오는 순간 DPI 독립성과 토큰 일관성(다크=베이클라이트/강철, 라이트=크림 알루미늄)이 깨집니다.
2. **모서리 3px = 기계 가공 코너.** 둥글지도 직각도 아닌, 모따기된 금속입니다. 모든 반지름 토큰(`--radius-xs`…`--radius-lg`)을 3px로 덮습니다(알약만 `--radius-pill` 유지).
3. **위계 = 물리 깊이.** 위계는 색이나 크기가 아니라 돌출(주요 컨트롤) / 평면(라벨) / 함몰(입력 우물)로 만듭니다. 돌출은 윗변 하이라이트 + 아랫변 그림자의 `box-shadow` 두 줄(한 방향 작업등: 상·좌 = 빛, 하·우 = 그림자), 함몰은 그 반전(그늘진 윗변 + 점등된 아랫입술)입니다. 함몰면은 부품으로 설계된 것(LCD 우물, 미터 창, 그래프 유리)만 허용합니다.
4. **상태 = 램프, 램프 = LED 문법.** 상태는 LED가 말하고, 모든 램프는 LED 문법(베젤 링 + 돔 + 스펙큘러, 후광은 점등 시에만)을 거칩니다. CSS로는 `radial-gradient`로 돔과 스펙큘러를, `box-shadow`의 안쪽 고리로 베젤을, 바깥 번짐으로 후광을 그립니다. 다크 마감에서 맨 발광 원반은 부품이 아니라 도료로 읽힙니다.
5. **전원 내림 = 비활성.** 비활성은 "전원 내린 유닛"입니다. LED를 끄고 어두운 필름(`--skin-film`)을 덮되 나사·결·각인은 남깁니다. 장비를 치우는 것이 아니라 끄는 것입니다.
6. **색 절제.** 액센트는 앰버(색상 62–70), 가동 램프는 LED 녹색(`--success`, 색상 163), 위험은 적색입니다. 주의(`--warning`)는 노란 램프(색상 88)로 앰버와 구분합니다(두 램프가 같은 색이면 '고른 것'과 '주의'가 섞입니다). 색은 램프와 각인에만 삽니다.
7. **표시창 조항.** 디스플레이(값 칸, 미터 창, 그래프 유리, 배치도 유리)는 패널 마감을 따르지 않고, 두 마감 모두 어두운 우물 + 발광 세그먼트로 그립니다. 크림색 패널에 박힌 LCD도 여전히 LCD이기 때문입니다. 세그먼트 잉크는 녹색 인광(`--skin-segment`), 활자는 모노 굵은체입니다.
8. **각인 조항.** 캡션과 머리글(레일 소제목, 카드 제목, 표 머리)은 자간을 띄운 대문자 각인풍 활자입니다(`text-transform: uppercase; letter-spacing: 0.08em`, 굵기 600). 한국어에는 대소문자가 없으므로 자간과 굵기만 적용됩니다. 문장(설명, 오류, 도움말)은 각인이 아니라 따뜻한 본문 잉크의 글입니다.
9. **따뜻한 잉크.** 글자는 따뜻한 상아색(다크 `oklch(0.91 0.017 85)`) 또는 짙은 갈색(라이트 `oklch(0.26 0.02 80)`)입니다. 차가운 흰색·회색을 쓰지 않습니다.
10. **판 위의 직접 페인팅.** 페이스플레이트에 앉는 요소(알약, 값 칸, 칩, 미터)는 자기 픽셀만 그립니다. 카드 면 위에 앱 바탕색 패치가 깔리면 각인이 '판에 새긴 글'이 아니라 '붙여 놓은 딱지'가 됩니다.

## 빛과 상태의 문법

- **hover:** 페이스플레이트 광택이 오르고(`--surface-hover`는 한 단 밝은 금속) 가장자리가 앰버로 덥혀집니다(1px 앰버 보더 예열). 리프트는 없습니다.
- **selected:** 따뜻한 패널 색(다크 `oklch(0.28 0.031 72)`, 라이트 `oklch(0.937 0.06 86)`)과 앰버 보더를 입습니다. 선택된 메뉴 항목과 표의 줄은 래치된 캡(반전 베벨, 면 1px 하강)입니다.
- **focused:** 앰버 서비스 엣지(2px 외곽선, 띄움 0)입니다. 기계의 선택 프레임이지 글로우가 아닙니다.
- **disabled:** 전원 내린 유닛입니다(불변 규칙 5).
- **빈 결과:** 플레이트의 각인입니다. `EmptyState`의 제목은 각인 활자로, 설명은 본문 잉크로 남깁니다.

## 구성 요소별 표현

### 앱 틀: 마스터 레일과 페이스플레이트 상단 스트립

레일은 랙의 세로 마운팅 레일입니다. 브러싱 결을 세로로 가지고(가로 결의 카드와 한 기계에서 잘라낸 판재), 단계 유닛 다섯을 1U 간격으로 장착합니다. 로고 타일은 황동 명판 자리에 앉되 그림은 그대로입니다(그림을 다시 그리지 않습니다). 단계 머리는 페이스플레이트 상단 스트립이고, 제목은 각인, 주 동작은 기계 캡, 막힌 이유는 노란 램프 + 본문 잉크의 한 줄입니다. 작업 트레이는 릴레이 패널(어두운 함몰 베드 위의 진행 세그먼트 바와 각인 캡션)입니다.

### 단추

주 동작은 위의 기계 캡입니다. 보조 단추는 민짜 캡(백라이트 없음, 같은 베벨), 조용한 단추는 패널에 납작하게 각인된 라벨(hover에 앰버 예열), 위험 단추는 적색 백라이트 legend의 캡입니다. 아이콘 단추는 정사각 캡입니다. 모든 캡은 눌리면 침강하고 떠오르지 않습니다.

### 카드와 섹션

카드 chrome(게이트 3)에 더해, 카드 제목은 자간 띄운 각인이고 도움말 단추는 작은 각인 캡입니다. '고급' 접힘은 서비스 해치(T-핸들 래치 대신 각인 캐럿 + 함몰 베드)입니다. 촘촘한 카드(`--dense`)는 나사를 생략하고 베벨만 남깁니다.

넓은 판의 빈 구간은 실제 장비처럼 하드웨어로 채웁니다. 내보내기의 형식 줄은 1U 출력 모듈이어서, 이름과 단추 사이에 일자 나사 두 개가 붙든 통풍 슬롯 띠가 들어갑니다. 글 몇 줄과 단추 하나만 놓인 넓은 판은 장비가 아니라 빈 양식처럼 보이기 때문입니다. 채움은 '하드웨어 페이스플레이트에 있을 물건인가'를 통과하는 부품(나사, 통풍 슬롯, 각인, 명판)으로만 하고, 시선을 끄는 추상 장식은 여전히 금지입니다(판례: 2026-10-23 사용자 판정, 파일 내보내기의 넓은 판이 글 덩어리뿐이라 매우 휑하다. 시선을 분산시킨다고 디자이너가 꺼릴 수 있어도 지루함을 없애는 것도 할 일이다).

### 입력칸, 선택기, 토글

값 칸은 LCD 우물(표시창 조항)이고 포커스는 앰버 서비스 엣지입니다. 선택기(`Select`)는 패널에 각인된 캡션 + 밑면의 밀링 홈 + 작게 인쇄된 삼각형이며, 열림은 앰버 예열입니다. 토글은 래칭 스위치(트랙은 함몰 베드, 손잡이는 돌출 캡, 켜짐은 앰버 램프창)입니다. 분할 단추(`Segmented`)는 캡 뱅크이고 고른 조각은 래치된 캡(반전 베벨 + 앰버 백라이트)입니다. 스테퍼의 ± 는 작은 기계 캡입니다.

### 표와 목록

표는 패널 인쇄입니다. 머리줄은 각인, 줄 경계는 1px 밀링 홈, 숫자 칸은 LCD 우물이 아니라 각인 숫자(표 전체를 우물로 만들면 판이 아니라 모니터가 됩니다). 칸에는 베벨을 두지 않습니다. 고른 줄은 캡이 아니라 콘솔의 어사인 램프 띠입니다. 줄 왼쪽 가장자리의 앰버 램프 띠가 켜지고 줄이 따뜻한 선택 패널 색을 입습니다(테두리 고리나 침강 없음). 줄은 판 위의 한 줄이지 누르는 부품이 아니기 때문입니다. (판례: 2026-10-22 사용자 판정, 채널별 성적표의 고른 줄이 캡처럼 보여 '표의 강조 문법'으로 읽히지 않았다)

### 미터

레벨 미터는 VU 세그먼트 창(표시창 조항)입니다. 어두운 우물에 1px 간격의 세그먼트, 적정 띠는 녹색 각인 구간, 클리핑은 적색 램프입니다. 최고값은 세그먼트 하나의 잔광입니다.

### 그래프와 배치도

그래프는 스코프 유리(게이트 8)이고, 채널 곡선 색은 데이터이므로 그대로입니다(토큰 유지). 축 숫자는 LCD와 같은 세그먼트 잉크의 굵은 모노이고, 유리 위의 인쇄 캡션(배치도의 방향 글과 축척)은 어두운 유리에서 읽히는 밝기의 상아색입니다. 라이트 마감에서는 유리가 밝은 크림 패널 한가운데 놓여 눈이 패널 밝기에 맞춰지므로, 유리 안 글자가 다크 마감에서보다 흐려 보입니다. 그래서 유리 안 글자는 패널의 본문보다 밝고 굵어야 합니다(판례: 2026-10-22 사용자 판정, 라이트 마감의 측정 화면에서 유리 안 글씨가 묻혀 보였다). 배치도는 글 없이 그림으로 말합니다. 스크린은 양 끝이 각진 2px 룰이고 그 아래 화살표가 스크린을 가리켜 '스크린 · 프론트 스피커 방향' 캡션을 대신하며, 좌석에도 라벨이 없습니다. 축척(30 cm)은 숫자가 곧 뜻이므로 자간을 띄운 인쇄 활자로 남습니다(판례: 2026-10-22 사용자 판정, 방향을 글로 적어 둔 것은 임시변통으로 때운 슬롭이다. 기본 스킨은 캡션을 두되 Rack·Matrix는 글 없이 전달한다. 화살표는 사용자의 안이고, 휜 스크린과 스피커 상자 시안은 슬롭으로 기각됐다). 그래프 위 도구 줄(단위, 커서 값, 축 범위 캡)은 유리 위에 자기 띠를 가지며 캡이 유리의 베젤에 닿지 않습니다. 타겟 점과 XO 손잡이는 앰버 조정 노브(돔 + 앰버 링)입니다. 배치도는 패널에 인쇄된 도면이고 고른 위치는 앰버 램프입니다.

### 팝오버, 메뉴, 대화상자, 토스트, 툴팁

팝오버와 메뉴는 떠 있는 서비스 패널(3px 코너, 베벨, 나사 없음)이고 고른 항목은 래치된 캡입니다. 대화상자는 서비스 해치(두꺼운 베벨 + 네 나사)입니다. 토스트는 서비스 노티스(패널 + 앰버 뉴스 킬 + 각인 닫기 캡)입니다. 툴팁은 다이모 엠보싱 라벨 테이프(광택 검정 스트립 + 양각 상아색 활자, 두 마감 모두 검정)입니다.

### 튜토리얼 레이어

코치 카드는 서비스 노티스 패널이고 강조 링은 앰버 서비스 엣지입니다. 튜토리얼 강조색(자홍)은 이 스킨에 없습니다. 이 기계의 램프 색은 앰버입니다(`[data-skin="rack"][data-accent]`가 앰버를 유지).

## 하지 말 것

- 이미지·SVG 에셋을 도입하지 않습니다. 전부 CSS로 그립니다(로고는 예외).
- 평면(flat) 디자인 어휘를 혼입하지 않습니다(채운 색 배지, 그림자 없는 순수 플랫 카드, 형광 액센트). 이 스킨에서 색은 램프와 각인에만 삽니다.
- 디스플레이(LCD/판독창)를 패널 마감에 맞추지 않습니다. 표시창은 언제나 어두운 우물입니다.
- 각인 조항을 카탈로그 문장에 적용하지 않습니다(설명·오류·도움말은 본문 잉크).
- 차가운 흰색/회색 텍스트를 쓰지 않습니다. 이 스킨의 잉크는 따뜻합니다.
- 램프를 맨 발광 원반으로 그리지 않습니다. 모든 램프는 LED 문법(베젤 + 돔 + 스펙큘러)을 거칩니다.
- 누름에 스케일 변화를 쓰지 않습니다. 캡은 침강합니다.
- 기본 스킨의 그림자 토큰을 그대로 두지 않습니다. 그림자는 베벨로 바뀝니다.

## 이웃 스킨과의 경계

Instrument도 깊이를 다루지만, Instrument의 깊이는 투명 그림자의 추상이고 Rack의 깊이는 부품의 물리(나사·베젤·함몰 우물)입니다. Matrix도 점등 어휘를 쓰지만, Matrix의 LED는 보드 위의 추상 신호(셀의 점등)이고 Rack의 LED는 베젤에 박힌 물리 부품입니다. Rack에서 격자 좌표나 모눈 질감, 라운드 0의 셀이 보이면 Matrix를 침범한 것입니다.

## 새 요소를 이 스킨답게 만드는 법

1. 이 요소의 실물 대응물은 무엇인가? (캡/스위치/명판/LCD/플레이트) 대응물이 없으면 은유부터 정한다.
2. 전부 CSS 그라디언트와 의사 요소로 그릴 수 있는가? 이미지가 필요해 보이면 설계를 바꾼다.
3. 깊이 배치를 정했는가? (돌출/평면/함몰)
4. 상태가 램프로 표현되는가? 비활성이 "전원 내림"으로 읽히는가?
5. 표시창이 있다면 두 마감 모두 어두운 우물 + 발광 세그먼트인가?
6. 각인 문구와 문장을 구분했는가?
7. 잉크가 따뜻한가?
