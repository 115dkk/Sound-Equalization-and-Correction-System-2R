# Dirac Live 프로젝트(`.liveproject`) 읽기

Dirac Live가 저장하는 프로젝트 파일에서 측정 IR을 꺼내는 방법입니다. 결정의 근거는 [ADR 0013](adr/0013-dirac-liveproject-import.md)에 있고, 읽기는 `secs-dirac`가, 가져오기는 `secs-service`의 `dirac_import`가 맡습니다.

Dirac Research는 이 형식을 공개하지 않았습니다. 아래 내용은 Dirac Live 3.14.3(Windows, Dirac Live Processor, 48 kHz)이 만든 프로젝트 11개를 바이트 단위로 살펴보고, 같은 파일에 함께 저장된 녹음으로 검산해 얻은 것입니다. 실행 파일은 열어 보지 않았고, 암호화된 덩어리는 건드리지 않습니다.

## 파일 구조

파일 전체는 Qt `QDataStream`입니다. 정수는 빅엔디언이고, `QString`은 바이트 길이(u32, `0xFFFFFFFF`는 null) 뒤에 UTF-16BE 본문이 옵니다. `bool`은 1바이트, `QByteArray`는 바이트 길이(u32) 뒤에 본문이 옵니다.

| 순서 | 형 | 표본 파일의 값 | 읽는가 |
| --- | --- | --- | --- |
| 1 | u32 | 10 | 형식 판으로 보관 |
| 2 | QString | 프로젝트 이름(파일 이름과 같음) | 예 |
| 3 | QString | `Live Desktop` | 예 |
| 4 | QString | Dirac 계정 사용자 ID(UUID) | 아니요 |
| 5 | QString | UUID(모든 표본에서 같음) | 아니요 |
| 6 | QString | 마이크 이름 | 예 |
| 7 | QString | 마이크 보정 파일 경로 | 아니요 |
| 8 | u32 | 0 | 아니요 |
| 9 | bool + QByteArray | 측정 세션(protobuf) | 예 |
| 10 | bool + QByteArray | 바이트당 엔트로피 8.00비트의 덩어리(암호화된 필터 설계로 추정) | 아니요 |
| 11 이후 | QString과 Qt 직렬화 값 | `3.14.3`, `2.2`, 프로세서 이름, 채널 이름, 필터 상태 | 아니요 |

사용자 ID와 보정 파일 경로는 개인 정보라 길이만 확인하고 건너뜁니다. 화면이나 프로젝트에 옮기지 않습니다.

## 측정 세션(protobuf)

9번의 본문은 protobuf 메시지입니다. 스키마가 없으므로 필드 번호와 와이어 형식으로 읽습니다. 표본에서 관찰한 필드는 다음과 같습니다. 굵게 쓴 필드만 읽습니다.

| 필드 | 형 | 내용 |
| --- | --- | --- |
| 1, 2 | string | UUID |
| 3 | varint | 세션 샘플레이트(48000) |
| 5 | varint | 채널 수 |
| **12** | message | **IR 묶음**(아래) |
| 14, 15 | bytes | float32 LE 배열 608개씩. 마이크 보정 곡선의 주파수(Hz)와 이득(dB) |
| 16, 17, 20 | string | `Dirac Research`, `Dirac_Live_Processor`, `Dirac Research AB` |
| 21 | string | 오디오 드라이버(`WASAPI_EXCLUSIVE`) |
| 24 | string | 마이크 이름 |
| 29 | message, 반복 | 입력 채널 배치 `{1: 번호, 2: 이름}` |
| **30** | message, 반복 | **출력 채널** `{1: 이름, 2: 종류, 3: 묶음, 4, 5: 대역 Hz, 6: 입력 번호}`. 종류는 1이 메인, 4가 서브우퍼입니다. |
| 50 | message, 반복 | 위치마다의 녹음 `{4: 위치 번호, 13: Ogg Vorbis 모노 48 kHz, …}` |
| 51 | message, 반복 | 녹음마다의 분석 값 `{1: 녹음 UUID, 31: 첫 채널 IR 구간의 시작 표본, 30: 채널별 float32, …}` |
| 60 | message | 스윕 `{1: 48000.0, 2: 10.0 Hz, 3: 24000.0 Hz, 4: 길이 240000, 5: 간격 24000, 6: 1, 7: 300.0}` |

### IR 묶음(필드 12)

| 필드 | 형 | 내용 |
| --- | --- | --- |
| 1 | varint | 샘플레이트 |
| 2 | varint | 채널 수 C |
| 3 | varint | 위치 수 P |
| 4 | message, C×P번 반복 | IR 하나 `{1: 샘플레이트, 5: float32 배율 s, 6: 부호 있는 16비트 빅엔디언 코드 배열}` |

IR은 위치 순서로 놓이고, 위치 안에서는 필드 30의 채널 순서를 따릅니다. 위치 p(0부터), 채널 c의 IR은 `p × C + c`번째입니다. 측정하지 않은 위치는 필드 6이 없는 IR로 남습니다(측정을 끝내지 않은 프로젝트에서 관찰).

코드 q는 μ-law(μ = 255)로 압신한 값이고, 한 IR의 가장 큰 |q|는 32767입니다. 선형 값은 이렇게 풉니다.

```text
x = s · 32767 · sign(q) · ((1 + μ)^(|q| / 32767) − 1) / μ,   μ = 255
```

IR 하나는 32769표본(48 kHz에서 0.683 s)입니다.

## IR의 성질

- **마이크 보정이 들어 있습니다.** 녹음에서 다시 만든 IR과 비교하면 대역별 차이가 필드 14·15 보정 곡선의 부호를 뒤집은 모양과 0.3 dB 안에서 같습니다. SECS 2R의 자체 측정과 REW mdat는 보정을 IR에 합치지 않으므로, Dirac에서 가져온 측정만 보정된 IR입니다. 이 IR을 REW mdat로 내보내 REW에서 보정 파일을 또 걸면 보정이 두 번 들어갑니다.
- **한 위치 안의 채널은 같은 시간 축을 씁니다.** 각 채널의 IR 구간은 재생 순서의 칸(264,000표본 = 스윕 240,000 + 간격 24,000)마다 같은 자리에서 시작하고, Dirac이 재생과 녹음의 클럭 차이(표본 프로젝트에서 약 10 ppm)를 보정해 칸마다 2–3표본씩 옮깁니다. 그래서 채널 사이의 도착 시각 차이가 남습니다.
- **위치 사이의 시간 축은 Dirac이 위치마다 따로 맞춘 것입니다.** 첫 채널의 도착은 대개 12,000번째 표본(250 ms) 근처에 오지만, 표본 프로젝트에서 10,900–12,100 사이를 오갔습니다. 위치 사이의 절대 지연은 알 수 없습니다.
- **IR 길이.** 도착 뒤에 약 0.43 s가 남습니다. 표본 프로젝트에서는 20–200 Hz 포락선이 이 안에서 잡음 바닥(피크 대비 −40~−50 dB)에 닿았습니다. 잔향이 긴 방이라면 감쇠 분석(MIMO의 늦은 에너지, 모드 T60)이 IR 끝에서 잘린 값을 봅니다.
- **레벨.** 위치와 채널 사이의 레벨 비는 그대로입니다. 절대 SPL은 알 수 없으므로 `spl_db`는 비워 둡니다.

## 가져오기 규약

- 시간 원점: 모든 IR의 `t0`를 −0.25 s로 둡니다(`secs_dirac::NOMINAL_ARRIVAL_S`). 도착이 REW처럼 0 근처에 오고, 엔진은 기준 위치의 가장 이른 도착을 0으로 다시 잡으므로 이 상수는 결과에 영향을 주지 않습니다.
- 위치: Dirac의 위치 p(0부터)를 SECS 2R의 위치 p + 1로 제안합니다. Dirac은 첫 측정을 주 청취 위치에서 하므로 기준 위치와 맞습니다. 프로젝트 배치보다 위치가 많으면 넘치는 위치는 가져오지 않습니다.
- 역할: Dirac 채널 이름(`Left`, `Right`, `Center`, `LeftSurround` 등)을 낱말로 나눠 역할을 제안하고, 서브우퍼는 채널 순서대로 SW1, SW2…를 제안합니다. 이름을 알아보지 못하면 제안하지 않고 사용자가 고릅니다.
- 출처: 측정 기록의 출처는 파일 이름입니다. REW `source_info`는 없습니다.

## 쓰지 않는 것

- **녹음(필드 50).** Ogg Vorbis 녹음을 스윕(10 Hz–24 kHz 지수 스윕, 5 s)으로 디컨볼루션하면 IR을 다시 만들 수 있고, 녹음을 Vorbis로 다시 압축해도 IR은 0.3 dB 안에서 같았습니다. 저장된 IR이 이미 Dirac 자신의 분석 결과(보정과 클럭 보정이 들어간 값)이고 표본 프로젝트에서는 저장된 구간 밖에 쓸 만한 신호가 남지 않았으므로, Vorbis 디코더를 들이지 않습니다.
- **10번 덩어리와 그 뒤의 프로세서 상태.** 필터 설계는 암호화돼 있고, 이것을 푸는 것은 이 기능의 범위가 아닙니다.

## 검증

표본 프로젝트(2–6채널, 위치 9곳, 11개 파일)로 다음을 확인했습니다. 표본 파일은 개인 정보가 들어 있어 저장소에 넣지 않습니다. 테스트는 같은 구조의 합성 파일을 씁니다.

1. 11개 파일 모두 위 구조로 끝까지 읽었습니다. 측정하지 않은 위치는 필드 6이 없습니다.
2. 녹음을 디컨볼루션한 IR과 저장된 IR을 같은 자리에 맞추면, μ = 255로 풀 때 50–80 Hz 대역 레벨 비가 모든 위치와 채널(36개)에서 0.05 dB 폭 안에 듭니다. μ = 240이나 270이면 0.37 dB, 200이나 320이면 1.4 dB로 벌어집니다.
3. 같은 비교에서 30 Hz–8 kHz 상관은 서브우퍼 0.998–0.999, 메인 0.96–0.99입니다. 메인에 남은 차이는 고역에 있고, 마이크 보정 곡선 때문입니다.
4. 선형 16비트로 잘못 풀면 상관이 0.70–0.80으로 떨어지고 잡음 바닥이 30 dB 넘게 올라갑니다.
