# 네이티브 GPU 경계

ADR 0008에 따라 `secs-cuda-sys`만 GPU 로더와 네이티브 호출의 unsafe를
가집니다. 예산은 `unsafe-budget.toml`에 있고 policy gate가 토큰을 셉니다.
`secs-gpu`, 엔진, 서비스와 앱의 코드는 안전한 API만 사용합니다.

## 공개 계약과 입력 검사

- `Runtime`은 동적 라이브러리를 소유하며, 장치 조회와 검사된 행렬의
  factor 생성만 제공합니다. 라이브러리 핸들·함수 포인터는 공개하지 않습니다.
- `SpectralSystem`은 장치 메모리, stream, cuSOLVER/cuBLAS 핸들을 소유하고
  생성된 스레드에서만 사용됩니다. Send/Sync를 손으로 구현하지 않습니다.
- 행렬은 정방형 크기와 RHS 길이, 유한 값, 대칭성, 정수 변환과 바이트 수
  오버플로를 검사합니다. workspace 조회의 반환 단위와 할당 범위를 검사한
  후에만 포인터를 라이브러리에 전달합니다.
- shifted solve의 λ와 결과를 검사합니다. 네이티브 호출 성공 코드뿐 아니라
  cuSOLVER의 devInfo와 복사된 수치도 확인합니다.
- 실패는 Result로 반환합니다. 안전한 잘못된 입력이 포인터 범위 위반이나
  미초기화 값 노출로 이어져서는 안 됩니다.

## unsafe 뒤에 숨긴 의무

| 경계 | 흡수하는 의무 |
|---|---|
| 라이브러리 로드·심벌 조회 | 지원한 ABI의 함수 시그니처, Windows의 절대 경로와 종속 DLL 검색, 함수 사용 동안 라이브러리 소유권 유지 |
| 장치 메모리 | 할당된 크기 안의 읽기/쓰기, 요소 수와 바이트 수 구분, 장치와 stream 일치 |
| 호스트/장치 복사 | 복사 동안 유효한 호스트 슬라이스, 완료 뒤에만 읽는 호스트 결과, 충분한 목적 버퍼 |
| 고유분해/GEMV | column-major 행렬·leading dimension·벡터 길이·workspace 크기·cuBLAS transpose 규약 |
| 해제 | 해당 장치 선택, 미완료 작업과 버퍼 수명, 부분 초기화 실패 시 획득된 자원만 해제, Drop에서 panic 금지 |

메모리 예산과 장치 lease는 상위 어댑터에서 한 factor와 그 shifted solve
전체를 감쌉니다. lease 대기와 호출 경계는 취소를 확인합니다. 이미 시작된
네이티브 고유분해를 장치 reset으로 중단하지 않습니다.

## 남는 신뢰와 검증

NVIDIA 라이브러리의 ABI·드라이버 구현은 외부 신뢰 경계입니다.
프로그램은 명시된 런타임 경로 또는 설치 위치를 사용하고 CPU fallback을
제공합니다. `mem::forget`으로 Drop이 실행되지 않으면 자원이 누수될 수
있지만 공개 API의 메모리 안전성이 Drop 실행에 의존하지는 않습니다.

입력 거절·지원 없음·오류 복구는 GPU 없는 CI에서도 검사합니다.
실제 GPU에서는 알려진 행렬의 고유계·shifted 해, λ 선택, 메모리 반복
사용과 취소를 검증합니다. 구현의 실제 함수·unsafe 수와 실측 결과는
최종 검토에서 이 계약에 대조합니다.

2026-10-19 부모 재검증의 policy gate는 `secs-cuda-sys` 47/80토큰을
보고했습니다. 검토 범위는 함수 포인터 ABI, 라이브러리 보존, 대칭·유한·
크기 검사, RHS 검사, stream 완료 뒤 readback, 부분 초기화와 Drop입니다.
버퍼는 `Rc<Session>`을 소유해 핸들보다 먼저 해제되며, 계산 객체는 `Rc`와
`PhantomData<Rc<()>>`로 생성 스레드에 묶입니다. 장치 선택·동기화에 실패한
Drop은 자원을 재사용하지 않고 반환합니다. 라이브러리/드라이버의 정확성은
외부 신뢰 경계로 남습니다.

## 작업 표시줄 아이콘 (secs-sys, ADR 0011)

### 공개 계약과 입력 검사

- `set_large_icon`은 `HasWindowHandle`을 빌려 받고 RGBA 슬라이스와 너비, 높이를
  받습니다. 원시 핸들과 `HICON`은 공개하지 않습니다.
- 너비와 높이는 각각 1부터 256까지인지 확인하고, 슬라이스 길이가
  `너비 × 높이 × 4`와 같은지 unsafe 호출 전에 확인합니다.
- Windows에서는 유효한 Win32 창 핸들만 받고, 핸들을 얻지 못하거나 다른
  플랫폼 핸들이면 오류를 반환합니다. 다른 운영체제에서는 입력 검사 뒤 아무
  작업 없이 성공을 반환합니다.
- 아이콘 생성 실패는 `LargeIconError::Create`로 반환합니다. 큰 아이콘 변경
  실패는 화면의 작은 아이콘 상태를 바꾸지 않습니다.

### unsafe 뒤에 숨긴 의무

| 경계 | 흡수하는 의무 |
|---|---|
| `CreateIcon` | 검사한 크기와 정확한 길이의 BGRA 색 비트맵, 호출 동안 살아 있는 0 AND 마스크, Win32가 복사한 뒤 버퍼 해제 |
| `SendMessageW` | 창을 소유한 스레드에서 호출, 빌린 핸들의 호출 동안 유효성, 생성한 `HICON`의 수명 |
| `DestroyIcon` | `WM_SETICON`이 돌려준 이전 큰 아이콘만 해제, 창이 더는 그 아이콘을 사용하지 않음, 마지막으로 설치한 아이콘은 해제하지 않음 |

### 남는 신뢰

`HasWindowHandle` 구현과 Win32의 창 및 아이콘 수명 규약은 외부 신뢰 경계입니다.
ADR 0011은 Tauri와 tao가 처음 큰 아이콘을 설치하지 않으며, 교체로 반환되는 0이
아닌 큰 아이콘은 이 함수의 앞선 호출이 만든 것이라고 정합니다. Windows 실제
작업 표시줄과 Alt+Tab 표시는 실기에서 확인하고, CI는 Windows 대상 clippy와 모든
운영체제에서 실행되는 입력 검사를 수행합니다.
