# 화면 결과 전송과 작업 기록 검증

2026-10-20. 기준 커밋은 `d8e0bd6`(0.20.0), 결정은 [ADR 0009](../adr/0009-compact-result-ipc-and-job-retention.md)입니다.

## 바꾼 데이터 경로

화면은 일반 보정의 메인·서브 역할과 개수, MIMO의 입력·경로·탭 수를
사용했습니다. 실제 FIR 계수를 사용하는 출하 UI 소비처는 없었습니다.
화면 요약에서 `SignalChain`과 `MimoPaths`를 제거하고 이 값들을 직접 전달합니다.
성적표, 지연, 계산 장치, 낡음과 안내 정보는 유지합니다.

보정·MIMO 완료 이벤트는 종류만 있는 표식을 보냅니다. 화면은 이후 `results`를
한 번 조회합니다. XO 추천·레벨·내보내기의 일회성 완료 값은 소비한 뒤 작업
목록에서 보관하지 않습니다. `JobSnapshot`에는 결과 필드 자체가 없습니다.
Rust 레지스트리, 화면 세션, 작업 트레이는 완료 32개와 모든 활성 작업을
보존합니다. 완료 요청 문맥은 정리하고, 초기 응답과 완료 이벤트의 순서가
뒤바뀌어도 결과 재조회를 중복하지 않습니다.

필터 원본은 Rust의 최신 계산 결과와 내부 캐시에 유지합니다. 캐시는 화면용
요약과 분리된 v4 형식으로 저장하며 v2/v3를 이주합니다. 132×8,000탭은 단일
JSON 원본도 기존 8 MiB 한도를 넘기므로 상한을 64 MiB로 조정했습니다.
크기가 제한된 임시 파일에 직접 직렬화하고, 파일 쓰기 동안 세션·결과 잠금을
유지하지 않습니다. 프로젝트를 교체하면 이전 계산은 새 프로젝트에 커밋할 수 없습니다.

## 실제 직렬화 크기

실제 `secs-types`를 그대로 복사해 Rust `serde_json`으로 직렬화했습니다.
고정 합성 입력은 MIMO **132개 경로 × 8,000탭 = 1,056,000개 f64**,
일반 보정은 **11개 메인 × 2,048탭 = 22,528개 f64**입니다.
동일한 역할·성적표·계산 메타데이터와 고정 시드의 계수 생성기를 사용했습니다.
변경 후 측정에서도 전체 필터 원본을 생성해 유지하며, 직렬화 대상만 바뀝니다.

| JSON 값 | 기준 바이트 | 변경 후 바이트 |
|---|---:|---:|
| MIMO 화면 요약 | 24,690,767 | 351 |
| 일반 보정 화면 요약 | 530,505 | 6,282 |
| 두 요약을 담은 `ResultsSummary` | 25,221,296 | 6,657 |
| MIMO 완료 이벤트 | 24,690,863 | 88 |
| 보정 완료 이벤트 | 25,221,399 | 95 |
| 완료 작업 스냅샷 | 24,690,894 | 94 |

현재 소스로 재현 도구를 별도 빌드해 변경 후 여섯 JSON의 바이트와 SHA-256이
첫 측정과 일치함을 확인했습니다. 역할 목록·입력 수를 기준 원본에서 다시
계산하고, 나머지 화면 메타데이터도 비교했습니다.

이 값은 해당 합성 입력의 UTF-8 JSON 크기입니다. 실제 프로젝트의 역할 수,
안내와 성적표에 따라 요약 크기는 달라지지만 FIR 탭 배열은 포함되지 않습니다.
계수 f64 원자료 8,448,000바이트와 JSON 24,690,767바이트는 다른 측정값입니다.

## JavaScript 보관 모델

Windows x64, Node 24.1.0 / V8 13.6에서 `--expose-gc`로 명시적 GC 뒤 힙을
측정했습니다. 기준 `state/session.ts`의 `host.jobs`처럼 완료 이벤트의 결과를
각 작업에 보관하고, 별도로 조회한 현재 결과도 보관하는 합성 모델입니다.
변경 후에는 결과 없는 완료 메타데이터 32개와 현재 요약만 보관합니다.
두 경우 모두 활성 작업 2개를 유지합니다.

| 완료 횟수 | 기준 보관 힙 증가량 | 변경 후 보관 힙 증가량 | 변경 후 완료 기록 수 |
|---|---:|---:|---:|
| 1 | 17,162,184 B | 23,728 B | 1 |
| 8 | 76,473,048 B | 24,896 B | 8 |
| 16 | 144,256,376 B | 48,664 B | 16 |
| 32 | 279,845,888 B | 50,544 B | 32 |
| 40 | 347,629,216 B | 50,640 B | 32 |

독립 재실행의 40회 값은 기준 347,627,888 B, 변경 후 43,216 B였습니다.
완료 기록 수와 활성 작업 수는 같았고, 작은 힙 측정값은 실행마다 달랐습니다.

입력 JSON 문자열은 미리 읽고 기준 힙에서 제외했습니다. 이 모델은 실제 React
상태 저장소나 WebView를 실행하지 않으며, IPC 브리지 복사·렌더링 지연·프로세스
RSS·전체 Rust 서비스 메모리는 측정하지 않습니다. 작은 힙 차이에는 런타임
잡음이 있습니다. 파싱·직렬화 시간도 원시 자료에 있으나 동시 작업을 배제하지
않은 마이크로벤치마크이므로 화면 정지 시간이나 앱 속도 향상의 근거로 사용하지 않습니다.

## 회귀 검증

- 타입 테스트는 보정·MIMO 완료 값이 128바이트 미만의 표식이고,
  작업 스냅샷에는 `result` 필드가 없음을 고정합니다.
- 서비스 테스트는 96개 작업 이후 최근 완료 32개와 오래 실행 중인 작업이
  남고, 마지막 활성 작업의 완료 이벤트도 전달되는지 확인합니다.
- 대형 캐시 테스트는 별도 합성 입력의 132×8,000 계수 전체를 저장·재열기 후
  비교합니다. 이 테스트의 캐시는 23,012,918바이트, 화면 요약은 611바이트입니다.
  위 직렬화 감사와 계수·메타데이터가 다르므로 숫자를 섞어 비교하지 않습니다.
- v2/v3 캐시 이주, 크기 제한 초과 시 이전 파일 보존과 임시 파일 제거,
  내보내기 전후 바이트 일치, 계산 중 프로젝트 교체를 검증합니다.
- 화면 테스트는 완료 기록 상한, 활성 작업 보존, 조기·중복 완료,
  늦은 목록 응답과 이전 프로젝트의 늦은 완료를 검증합니다.

정량 자료는 [감사 JSON](compact-ipc-repro/compact-ipc-audit.json)과
[비교 CSV](compact-ipc-repro/payload-comparison.csv), 재현 방법은
[실행 안내](compact-ipc-repro/README.md)에 있습니다. 큰 합성 JSON과 바이너리는
저장소 밖에 생성합니다.

로컬 Windows에서 전체 Rust 테스트, workspace 및 Windows 대상 Clippy,
경고를 오류로 처리하는 rustdoc, cargo-deny, 정책 테스트 20개와 Python 보조
테스트 44개를 통과했습니다. 업스트림 트리도 고정 커밋과 일치합니다.
기능 등록부의 실제 컴파일 목록 검사는 Windows에서 제외되는 기존
`secs-sys::callback_native_sample_conversion` 한 항목 때문에 로컬에서는
통과하지 않습니다. 새로 등록한 테스트들은 모두 목록에 있으며, 전체 검사는
Linux CI에서 확인합니다.
