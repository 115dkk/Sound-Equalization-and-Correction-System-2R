# 네이티브 GPU 검증 — 2026-10-19

출하 경로는 Python 없이 CUDA 13/cuSOLVER/cuBLAS를 동적으로 읽는 f64
FIR 선형계 풀이입니다. Windows 11, i5-12600KF(논리 16스레드), RTX 2080
SUPER 8 GiB, CUDA 13.4에서 검증했습니다. CPU 기준은 기존 순차
Householder RidgeSweep이며 CPU 누적 순서를 유지합니다.

## 같은 선형계의 정칙화 탐색

`secs-gpu`의 `ridge_probe`는 기록한 실제 `big/L`의 ATA·ATb·LP·직접 응답을
읽고 출하 코드의 19회 λ 탐색을 재생합니다. 2160차는 원래 12경로×180탭
문제이고, 작은 사례는 같은 행렬에서 경로별 탭을 추출한 부분 문제입니다.
각 백엔드 1회 준비 실행 뒤 5회 중앙값입니다. GPU 시간에는 할당, 업로드,
분해, 19회 해·보정·읽기, CPU의 에너지 판정 및 해제가 포함됩니다.
파일 읽기와 런타임 검색은 측정 밖입니다. 두 백엔드는 순차로 측정했습니다.

| 차수 | CPU (초) | GPU (초) | CPU/GPU |
|---:|---:|---:|---:|
| 512 | 0.017312 | 0.039663 | 0.44 |
| 720 | 0.037544 | 0.057932 | 0.65 |
| 840 | 0.066236 | 0.068436 | 0.97 |
| 1024 | 0.109874 | 0.076496 | 1.44 |
| 2160 | 1.175766 | 0.332859 | 3.53 |

모든 사례에서 19개 탐색 분기와 선택 λ가 일치했습니다. 2160차의 선택 해
상대 L2 오차는 1.12e-9, 에너지 비율 궤적의 최대 절대 차이는 2.98e-12입니다.
840차는 각각 3.36e-10, 1.56e-12입니다. 검사 기준은 상대 해 오차 1e-6,
에너지 비율 차이 1e-8 및 탐색 분기 일치입니다.

초기 spectral 해만 사용한 840차에서 에너지 차이 기준을 근소하게 넘어서,
CPU 기준과 같은 순서로 잔차를 만든 뒤 GPU 분해로 한 번 보정합니다.
위 표는 이 보정을 포함합니다. 자동 모드의 최소 차수는 실측에 따라 1024로
유지했습니다. **3.53배는 이 커널의 수치이며 앱 전체 가속률이 아닙니다.**

## 끝단 음향 결과와 적용 범위

`mimo_probe`는 실제 production fitter와 모든 측정 위치의 응답을 사용합니다.
CPU/GPU를 각각 한 번 실행한 아래 시간은 기능 검증 기록이며 성능 중앙값은
아닙니다. 출하 스레드 수 16, 명시적 GPU 선택으로 작은 문제까지 비교했습니다.

| FIR 사례 | CPU/GPU 시간(초) | 최종 SPL 최대 차이(dB) | CPU/GPU 경로 수 |
|---|---:|---:|---:|
| room | 0.178 / 0.333 | 3.52e-10 | 12 / 12 |
| room_dba | 0.246 / 0.416 | 4.21e-9 | 18 / 18 |
| big | 1.450 / 2.111 | 9.03e-10 | 132 / 132 |

FIR 세 사례의 늦은 에너지 최대 차이는 1.03e-9 dB, 대역 가드 차이는
1.54e-9 dB, modal-tail 지표 차이는 5.33e-11입니다. 경로 수와 가드 판정이
일치했습니다. 이 세 사례는 840차 이하이므로 자동 설정은 CPU를 사용합니다.
명시적 GPU 선택은 작은 문제에서 더 느릴 수 있습니다.

IIR 모드는 별도로 실패를 확인했습니다. 이상 목표의 상대 오차는 1.1e-8
이하여도 최종 SPL 최대 차이가 room 0.557 dB, room_dba 3.351 dB,
big 1.979 dB였고 뒤 두 사례의 경로 수가 달라졌습니다. 자체 음향 가드
통과만으로 CPU 동등성을 보장하지 못했습니다. 따라서 출하 경로는 IIR의
이상 목표 설계부터 CPU를 유지하고 결과에 `iir_reference` 사유를 기록합니다.

위 실험의 표본·궤적·음향 지표는 [원시 감사 기록](gpu-audit.json)에 있습니다.
IIR 실패 기록은 범위 결정을 설명하기 위해 보존했습니다.

## 출하 정책의 전체 실행 검증

IIR 제한을 적용한 뒤 `room`과 `room_dba`를 CPU와 명시적 GPU 선택으로
다시 실행했습니다. 두 경우 모두 실제 CPU 계산이며 목표·필터·응답이
비트까지 일치했습니다. 결과의 사유는 `iir_reference`이고 경로 수는 각각
8개·17개입니다. 기본 `big` FIR의 자동 선택도 실제 CPU 11개 시스템과
`small_problem` 사유를 확인했습니다.

자동 GPU를 시험하기 위해 기존 모달 방 생성법을 정식 역할 27개(메인 19개,
서브 8개)로 확장한 **합성 스트레스 사례 `big_fir`**를 추가했습니다. 최대
26개 서포트×70탭의 1820차 문제입니다. 실제 방 녹음 데이터는 아닙니다.
Context 16, 백엔드별 준비 실행 1회 뒤 3회를 CPU/GPU 순서로 측정했습니다.
측정 중 다른 빌드·테스트를 실행하지 않았고, 사전 보정 설계와 지표 계산은
시간 밖이며 한 번의 MIMO 계산 전체가 시간 안입니다.

| 경로 | 본 측정 3회(초) | 중앙값(초) |
|---|---|---:|
| CPU | 11.095113, 11.159705, 11.336002 | 11.159705 |
| 자동 CUDA | 6.631637, 6.876349, 6.905228 | 6.876349 |

전체 MIMO가 **1.62배, 약 38.4% 짧아졌습니다**. 자동 CUDA는 선형계 19개를
처리했고 CPU fallback은 0개입니다. 최종 경로 104개가 일치했으며 이상 목표
상대 L2 차이는 3.73e-11, 최종 SPL 최대 차이는 1.63e-10 dB입니다. 모든
위치의 늦은 에너지·대역·modal-tail 가드와 경로 수를 엄격 대조했습니다.
이는 큰 합성 사례 한 건의 전체 실행 측정이며 일반 방·모든 GPU의 배수를
보장하지 않습니다. 앞선 기능 검증 실행과 이 반복 측정은 원시 기록에서
별도 phase로 구분합니다.

## 재현과 적용 한계

```text
cargo test -p secs-cuda-sys --release -- --ignored --nocapture
cargo run -p secs-gpu --release --example ridge_probe -- <recorded-problem-directory>
cargo run -p secs-gpu --release --example mimo_probe -- room fir
cargo run -p secs-gpu --release --example mimo_probe -- room_dba fir
cargo run -p secs-gpu --release --example mimo_probe -- big fir
```

큰 FIR 자동 선택 반복 측정은 `SECS_GPU_PROBE_AUTO=1`, `SECS_PERF_RUNS=3`,
`SECS_PERF_THREADS=16`을 설정하고 `mimo_probe -- big_fir fir`로 실행합니다.

행렬 기록 디렉터리는 `meta.json`, little-endian f64의 `ata.f64`, `atb.f64`,
`lp.f64`, `direct.f64`를 받습니다. 큰 감사 입력 자체는 저장소에 넣지 않습니다.
GPU 없는 CI는 장치 정책, 취소, 가짜 장치 손실 뒤 전체 CPU 재시작, 캐시와
CLI/UI 계약을 검사합니다. 네이티브 하드웨어 시험은 CUDA 런타임과 적격
장치가 있는 호스트에서 별도로 실행합니다.

이번 하드웨어 실측은 NVIDIA 장치 한 종류와 Windows입니다. 다른 장치의
전체 처리량, Linux의 실제 GPU 실행과 장시간 장치 오류 복구는 추가 검증
대상입니다. GPU 한 대의 lease는 분해부터 탐색이 끝날 때까지 유지합니다.
CPU 입력 병렬도, GPU 요청 직렬화, 행렬 크기에 따라 전체 실행 이득이 달라집니다.

## 로컬 검사

부모가 workspace 전체 테스트·doc-test, 두 Clippy 대상, 포맷, rustdoc
경고 거절, cargo-deny, 정책 게이트, CI Python 테스트와 업스트림 보존 검사를
실행했습니다. 최신 네이티브 경계는 해·보정 RHS·입력 거절·취소·반복 장치
메모리 해제를 포함한 5개 테스트가 실제 GPU에서 통과했습니다. CLI에서 적격
GPU의 자동 CUDA 선택과 런타임 경로가 없는 환경의 자동 CPU 선택도 확인했습니다.

UI는 깨끗한 `npm ci` 후 타입 검사·398테스트·배포 빌드와 최종 48화면 검사를
통과했습니다. 자세한 검토는 [UI 기록](gpu-ui-review.md)에 있습니다.

Windows에서 기능 등록부의 테스트 목록 검사는 기존
`secs-sys::callback_native_sample_conversion` 하나만 누락으로 보고합니다.
이 테스트가 있는 CPAL 모듈은 비 Windows 전용이고, 변경 전 등록부에도 같은
참조가 있습니다. GPU 신규 참조는 모두 컴파일됩니다. 기존 CI처럼 Linux에서
플랫폼 제한 없는 전체 등록부 검사를 실행합니다.
