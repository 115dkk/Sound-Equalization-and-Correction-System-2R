# 해석적 미분 실험장

v0.26.0의 리소스 최적화에서 뺀 변경 가운데 해석적 미분 두 가지를, 기본값을 바꾸지 않는 실험 설정으로 남긴 문서입니다. 일반 PEQ 맞춤과 MIMO IIR 맞춤이 각각 미분을 차분 근사 대신 닫힌 식으로 계산하게 할 수 있습니다. 둘 다 꺼져 있으면 계산 결과가 이전 판과 비트까지 같습니다. 같은 측정에서 업스트림 방식과 해석적 미분의 결과를 내 Dirac Live ART와 비교하고, Dirac에 더 가까운 쪽을 고르는 데 쓰려고 만들었습니다.

| 설정 | CLI | 엔진 |
|---|---|---|
| PEQ 맞춤 해석적 미분 | `project set --peq-derivatives analytic` | `CalibrationSettings::peq_analytic_derivatives`, `PeqDerivatives` |
| MIMO IIR 맞춤 해석적 미분 | `project set --mimo-iir-derivatives analytic` | `CalibrationSettings::mimo_iir_analytic_derivatives`, `IirDerivatives` |

데스크톱 앱에서는 보정 화면 › 보정 범위 › 고급의 '해석적 미분 (실험)' 하나로 두 설정을 함께 고릅니다. 선택지는 '쓰지 않음(기본값)', '일반 PEQ', 'MIMO IIR', '둘 다'입니다.

이 문서는 바뀌는 식, 시뮬레이션에서 잰 값, 실험장 쓰는 법, Dirac과 비교하는 절차를 차례로 적습니다. 편차 번호는 D43(MIMO IIR)과 D44(PEQ)이고 근거는 [ADR 0012](../adr/0012-resource-optimizations.md)의 보충 절입니다.

## 1. 무엇이 바뀌는가

### PEQ 맞춤

`fit_peq`는 룸 보정(RC), 크로스오버 PEQ, 서브 버스 PEQ, XO 추천, MIMO 시드의 시작 PEQ를 맞춥니다. 잔차는 맞춤 구간 안에서 가중 1, 밖에서 0.15인 dB 차이입니다.

```text
r_i(θ) = w_i · (20·log10(|H(f_i)| + 1e-12) − corr_i),   H = Π_k P_k
```

업스트림(기본값)은 SciPy `least_squares`의 기본값과 같은 2점(전진) 차분으로 Jacobian을 만듭니다. 해석적 미분을 고르면 아래 닫힌 식을 같은 경계 TRF(정확 SVD, 평가 한도 400회, 링잉 제한 맞춤은 150회)에 넘깁니다.

```text
∂r_i/∂θ = w_i · (20/ln 10) · |H| / (|H| + 1e-12) · Re( (1/P_k)·∂P_k/∂θ )
```

`|H|/(|H| + 1e-12)`는 잔차에 더한 1e-12를 그대로 미분한 항입니다. 이 값을 없애거나 `log10(|H|)`의 미분으로 바꾸지 않았습니다. `(1/P_k)·∂P_k/∂θ`는 아래 피킹 PEQ 식입니다.

### MIMO IIR 맞춤

MIMO IIR은 주 채널 하나를 재생할 때 다른 스피커(서포트)가 보정 신호를 함께 내서 20–150 Hz의 늦은 에너지를 줄입니다. 서포트 경로 하나의 전달함수와 변수는 아래와 같습니다.

```text
H(f) = 10^(g/20) · polarity · exp(-j·2π·f·τ/1000) · Π_k P_k(f) · Π_a A_a(f)

x = [g(dB), τ(ms), (ln f0, ln Q, G dB) × K개 PEQ, (ln f0, ln Q) × A개 올패스]
```

`P_k`는 48 kHz RBJ 피킹 필터, `A_a`는 아날로그 2차 올패스입니다. 변수를 맞추는 최적화는 두 번 있습니다.

- **시드 맞춤(`fit_one`):** 서포트 경로 하나를 혼자 목표 응답에 맞춥니다. 경계가 있는 TRF이고 평가 한도는 300회입니다. 업스트림은 2점 차분입니다. 시드의 시작 PEQ는 `fit_peq`로 맞추므로 PEQ 설정을 따릅니다.
- **결합 맞춤(`solve_joint`):** 모든 서포트를 함께 맞추고, 잔차는 위치별 늦은 에너지, 노력, 레벨, 이득 항입니다. 평가 한도는 `Tuning::mimo_max_nfev`(기본 150회)입니다. 업스트림 `mimo_iir.py`와 같이 PEQ·올패스 변수를 h=10⁻⁴ 중앙차분으로 미분하고, 이득과 지연 열은 원래 해석적입니다.

해석적 미분을 고르면 두 맞춤 모두에서 PEQ와 올패스 인자의 로그 미분 `(1/P)·∂P/∂θ`를 닫힌 식으로 계산하고 `∂H/∂θ = H · (1/P)·∂P/∂θ`를 씁니다. 목적함수, 경계, 평가 한도, TRF 반복은 그대로이고 미분만 바뀝니다.

### 피킹 PEQ의 로그 미분

`a = 10^(G/40)`, `w = 2π·f0/fs`, `α = sin w / (2Q)`, `z = exp(-j·2π·f/fs)`, `u = 1 - z²`라 두면 RBJ 계수의 분자와 분모는 다음과 같습니다.

```text
N(z) = (1 + α·a) - 2·cos w · z + (1 - α·a)·z²
D(z) = (1 + α/a) - 2·cos w · z + (1 - α/a)·z²
```

로그 미분은 `∂N/N - ∂D/D`이고, 각 변수의 `∂N`, `∂D`는 아래와 같습니다.

| 변수 | ∂N | ∂D |
|---|---|---|
| ln f0 | `α_f·a·u + m_f·z` | `α_f/a·u + m_f·z` |
| ln Q | `-α·a·u` | `-α/a·u` |
| G (dB) | `(ln 10/40)·α·a·u` | `-(ln 10/40)·α/a·u` |

여기서 `α_f = w·cos w / (2Q)`는 `∂α/∂ln f0`, `m_f = 2w·sin w`는 `∂(-2 cos w)/∂ln f0`입니다. 분자와 분모를 따로 나누므로 아주 작은 대역 응답으로 전체 곱을 나누는 일이 없습니다. 구현은 `secs_dsp::response::peaking_log_derivatives_z`입니다.

### 아날로그 올패스의 로그 미분

`s = j·f/f0`, `N = s² - s/Q + 1`, `D = s² + s/Q + 1`이면 다음과 같습니다.

```text
∂ln A/∂ln f0 = (-2s² + s/Q)/N - (-2s² - s/Q)/D
∂ln A/∂ln Q  = (s/Q)/N - (-s/Q)/D
```

올패스는 크기가 1이므로 이 미분의 실수부는 0입니다. 단위 테스트가 이것을 확인합니다. 구현은 `secs_dsp::response::allpass_log_derivatives`입니다.

## 2. 미분 자체는 더 정확합니다

MIMO IIR의 `room_C` 기록 문제에서 해석적 JᵀJ와 중앙차분 JᵀJ를 비교하면, f64에서는 h를 줄여도 차이가 줄지 않습니다. 48 kHz 저역 RBJ 계수 합에서 자릿수가 사라지기 때문입니다. 인자 응답만 확장 정밀도(`longdouble`, ε≈1.08×10⁻¹⁹)로 계산하면 차이가 h²에 맞춰 줄어듭니다. 그러므로 기존 오라클(h=10⁻⁴)과 해석적 미분의 차이 2.69×10⁻⁶은 중앙차분의 절단오차입니다.

| 중앙차분 h | f64 JᵀJ와 해석적 JᵀJ의 상대 최대 차이 | 인자만 확장 정밀도로 계산한 차이 |
|---:|---:|---:|
| 10⁻⁴ | 2.69×10⁻⁶ | 2.67×10⁻⁶ |
| 10⁻⁵ | 3.36×10⁻⁷ | 2.65×10⁻⁸ |
| 10⁻⁶ | 3.24×10⁻⁶ | 9.86×10⁻¹⁰ |

재현은 `python3 docs/perf/resource-iir-derivative-check.py`이고 결과 표본은 [`resource-iir-derivative-check.json`](resource-iir-derivative-check.json)입니다(NumPy 필요). 이 컨테이너(Python 3.13, NumPy 2.5.3)에서 다시 돌려도 표본과 같은 값이 나왔습니다.

Rust 쪽에서도 같은 차이가 나옵니다. `mimo_iir_functions_match_dense_oracle`은 기본값(중앙차분)이 오라클을 10⁻¹⁰ 안에서 재현하는지 확인하고, 해석적 미분의 차이를 따로 잽니다. room_C의 JᵀJ 차이는 2.687×10⁻⁶으로 파이썬 진단과 같고, 6개 사례의 최대는 room_L의 2.92×10⁻⁵입니다. 테스트 상한은 이 최댓값의 1.5배입니다. PEQ 맞춤의 Jacobian은 단위 테스트가 5점 차분과 비교합니다.

## 3. 시뮬레이션에서 잰 값

### PEQ 맞춤

PEQ 해석적 미분만 켠 판을 v0.26.0 작업 때 판정했습니다. 두 검사는 통과하고 하나가 실패했습니다.

- **맞춤 하나하나:** 오라클이 기록한 `fit_peq` 호출 97건을 해석적 미분으로 다시 풀면 모두 SECS 2의 실행 간 폭 안에 듭니다. SECS 2 12벌 모두보다 비용이 나쁜 호출은 5건, 기준 실행보다 비용이 낮은 호출은 81건입니다.
- **설계 끝단(`engine_e2e_spread`):** 통과합니다.
- **XO 추천 범위(`xo_recommendation_production_envelope`):** 실패합니다. room 센터 100 Hz의 GD 폭이 34.46 ms로 SECS 2 폭(32.23–32.60 ms)의 3배를 넘고, dolby 서라운드 100 Hz의 점수가 86.54로 SECS 2(86.76–86.82)의 3배를 넘었습니다.

골든 방 10곳의 설계 결과는 모두 달라졌고, 방향은 일정하지 않았습니다.

### MIMO IIR 맞춤: 늦은 에너지

전체 MIMO 실행(`mimo::run::compute`)을 같은 설계 결과에서 두 방법으로 돌려 주 채널마다 늦은 에너지를 쟀습니다. PEQ 설정은 기본값입니다. 늦은 에너지는 `decay::late_db_20_150`입니다. 응답에 4차 버터워스 20–150 Hz 대역통과를 걸고, 도착 뒤 150–400 ms 에너지를 처음 50 ms 에너지와 비교한 dB입니다. 아래 표의 감소량은 MIMO 뒤 값에서 앞 값을 뺀 것이라 음수가 클수록 좋고, 차이는 해석적 미분에서 중앙차분을 뺀 값이라 음수면 해석적 미분이 낫습니다.

### MIMO IIR 맞춤: 속도

## 4. 실험장 쓰는 법

### 설정의 성질

두 설정은 보정 설정의 일부라 프로젝트 파일에 저장됩니다. 켜거나 끄면 다른 보정 설정을 바꿨을 때와 같이 지금 결과가 낡은 결과가 되고, 다시 계산해야 곡선과 내보내기에 쓰입니다. PEQ 설정은 보정 결과와 MIMO 결과 모두에, MIMO IIR 설정은 MIMO 결과에만 영향을 줍니다. MIMO IIR 설정은 MIMO를 FIR로 계산할 때 쓰이지 않습니다. GPU 가속을 골라도 IIR은 늘 CPU 기준 계산을 쓰므로 계산 기기 선택과는 상관이 없습니다.

### 데스크톱 앱

보정 화면의 '보정 범위' 카드에서 '고급'을 열면 '해석적 미분 (실험)'이 있습니다. 고르면 두 설정이 한 번에 바뀝니다. MIMO IIR 쪽은 MIMO를 켜고 '서포트를 FIR로 계산'을 끈 IIR 계산에서만 쓰이며, 그렇지 않은 상태에서 MIMO IIR이 들어간 선택지를 고르면 그 사실을 한 줄로 알려 줍니다. 실험 설정이 켜진 채로 프로젝트를 열면 이 '고급'이 처음부터 열려 있습니다.

### CLI

CLI는 `project set`으로 같은 설정을 바꾸고 프로젝트를 저장합니다. 실험에 필요한 MIMO 켜기와 서포트 종류도 같은 명령으로 바꿉니다. 값을 주지 않은 설정은 그대로 두고, 아무 값도 주지 않으면 지금 설정을 출력만 합니다.

```sh
secs2r-cli project set lab.secs --mimo on --mimo-supports iir                                  # MIMO IIR로 계산
secs2r-cli project set lab.secs --peq-derivatives two-point --mimo-iir-derivatives central   # 기본값
secs2r-cli project set lab.secs --peq-derivatives analytic                                   # PEQ만 실험
secs2r-cli project set lab.secs --mimo-iir-derivatives analytic                              # MIMO IIR만 실험
```

Dirac Live `.liveproject`의 측정을 가져와 네 조합을 모두 내려면 아래처럼 하십시오. 프리셋과 서브우퍼 수는 Dirac 프로젝트의 채널 배치에 맞추십시오.

```sh
secs2r-cli project new lab.secs --preset 5.1 --subs 2
secs2r-cli import-mdat lab.secs dirac.liveproject
secs2r-cli project set lab.secs --mimo on --mimo-supports iir
for peq in two-point analytic; do
  for iir in central analytic; do
    secs2r-cli project set lab.secs --peq-derivatives $peq --mimo-iir-derivatives $iir
    secs2r-cli run --project lab.secs --mimo --out out-$peq-$iir
  done
done
```

`out-*/export/` 아래에 CamillaDSP, Equalizer APO, 필터 글, 보정 전후 mdat가 조합마다 따로 생깁니다. 보정 전후 mdat에는 MIMO를 포함한 예측 응답이 들어 있으므로, 이것을 REW나 스크립트로 읽어 3절과 같은 지표를 구할 수 있습니다. 가져오기의 세부(위치 번호, 역할 제안, 마이크 보정)는 [`DIRAC_LIVEPROJECT.md`](../DIRAC_LIVEPROJECT.md)에 있습니다.

`.liveproject`에서 SECS 2R이 읽는 것은 측정 IR과 채널 정보뿐입니다. Dirac이 계산한 필터는 암호화된 덩어리로 저장되어 있어 읽지 않습니다. 그래서 Dirac 쪽의 비교 기준은 프로젝트 파일에서 나오지 않고, Dirac ART를 켠 상태로 따로 잰 측정이 있어야 합니다.

### 시간 재기

조합 사이의 계산 시간을 비교하려면 같은 기계에서 명령을 번갈아 세 번 이상 돌려 중앙값을 쓰십시오. 3절의 시간은 MIMO 단계만 잰 값이고, `run`은 보정과 내보내기 시간도 포함합니다.

## 5. Dirac Live ART와 비교

Dirac이 공개한 설명으로는 ART가 20–150 Hz에서 동작하고, 모든 스피커와 방을 하나의 MIMO 시스템으로 다뤄 저음이 남는 시간을 줄입니다([Denon의 Dirac Live 설명서](https://manuals.denon.com/DiracLive/ALL/EN/DRDZSYeewuvdnn.php), [StereoNET의 Dirac 인터뷰](https://www.stereonet.com/uk/features/inside-track-dirac-live-active-room-treatment/)). SECS 2R의 MIMO IIR도 같은 대역(늦은 에너지 대역통과 20–150 Hz, `fsiso` 기본 150 Hz)에서 같은 일을 하므로 같은 지표로 비교할 수 있습니다. ART의 내부 알고리즘은 공개되지 않았고 이 저장소에서 확인하지 않았습니다.

### 비교할 것

아래 결과들을 같은 지표로 놓고 비교하십시오.

| 결과 | 얻는 방법 |
|---|---|
| SECS 2R 기본값 | 두 설정을 끈 채 낸 예측 응답, 또는 그 설정으로 재생해 잰 응답 |
| SECS 2R 실험 조합 | 한쪽이나 양쪽 설정을 켜고 낸 예측 응답, 또는 그 설정으로 재생해 잰 응답 |
| Dirac Live ART | ART를 켜고 같은 위치에서 잰 응답 |

예측 응답끼리, 실측 응답끼리 비교하는 것이 원칙입니다. SECS의 예측 응답을 Dirac의 실측과 바로 비교하면 SECS의 예측 오차가 차이에 섞입니다. Dirac 쪽은 실측만 있으므로, 실험 조건이 허락하면 SECS 쪽도 재생해 잰 응답으로 비교하십시오. Dirac 측정을 가져온 IR에는 Dirac의 마이크 보정이 이미 들어 있고 도착 뒤 약 0.43 s까지만 저장되어 있습니다. 늦은 에너지 구간(도착 뒤 150–400 ms)은 이 안에 들어가지만, 잔향이 긴 방이라면 IR 끝에서 잘린 값을 봅니다.

### 지표

위치마다, 주 채널마다 아래 값을 구하십시오. 첫 지표가 SECS MIMO의 목적함수와 정의가 같으므로 핵심 지표입니다.

- **20–150 Hz 늦은 에너지:** `late_db_20_150`과 같은 정의입니다(4차 버터워스 20–150 Hz, 도착 뒤 150–400 ms 대 처음 50 ms의 dB). 주 채널 하나를 재생할 때 MIMO 서포트도 함께 나와야 하므로, 실측이라면 보정을 켠 상태에서 채널을 하나씩 재생해 재십시오.
- **1/3 옥타브 감쇠 시간:** 20–150 Hz의 T20 또는 T30입니다.
- **크기 응답:** 20–150 Hz에서 목표 곡선과의 차이입니다. PEQ 설정의 효과는 주로 여기와 군지연에 나타납니다.
- **군지연:** 20–150 Hz 군지연이고, 폭포 그림도 함께 남기면 비교하기 쉽습니다.

### 판정

Dirac ART와 더 비슷한 결과를 내는 쪽을 고르는 것이 이 실험의 기준입니다. 위치·채널·대역마다 `|SECS 지표 − ART 지표|`를 구해 조합끼리 비교하십시오. 두 설정을 따로 켠 조합이 있으므로 어느 설정이 차이를 줄이거나 늘리는지 나눠 볼 수 있습니다.

판정 전에 두 가지를 정해 두어야 합니다.

- **측정 반복 폭:** 같은 조건을 최소 세 번 다시 재서 지표가 얼마나 흔들리는지 구하십시오. 조합 사이의 차이가 이 폭보다 작으면 무승부입니다.
- **사례 수:** 시뮬레이션에서 두 해석적 미분은 채널마다 좋아지기도 나빠지기도 했습니다(3절). 방 하나, 위치 하나의 결과는 우연일 수 있으니 위치를 여럿 쓰고, 할 수 있으면 방이나 배치를 바꿔 다시 비교하십시오.

### 기본값으로 바꾸려면

해석적 미분이 이기더라도 기본값을 바꾸면 PEQ는 `xo_recommendation_production_envelope`가, MIMO IIR은 `mimo_iir_joint_costs_within_spread`가 실패합니다. 이 검사들의 상한을 조용히 넓히지 말고 아래 순서로 바꾸십시오.

1. ADR 0004의 판정 규칙에 예외를 두는 ADR을 먼저 쓰십시오. Dirac 비교의 조건, 지표, 결과를 근거로 남기고, 이 편차는 SECS 2의 결과 분포 대신 그 비교로 판정한다고 적으십시오.
2. `docs/DEVIATIONS.md`의 D43이나 D44를 기본값 변경으로 고치고, 해당 검사를 그 ADR에 맞게 바꾸십시오.
3. CHANGELOG에 사용자에게 달라지는 점(결과가 바뀜, 계산 시간)을 적으십시오.

## 6. 확인하지 못한 것

- 해석적 미분으로 만든 보정값을 실제 방에서 재생한 적이 없습니다. 3절의 값은 모두 골든 사례의 측정으로 계산한 시뮬레이션입니다.
- 골든 사례는 설계 10곳, MIMO IIR 전체 실행 4곳, 결합 맞춤 기록 6건뿐입니다.
- PEQ 해석적 미분을 켰을 때의 계산 시간은 따로 재지 않았습니다.
- Dirac ART의 내부 동작과 목적함수는 공개되지 않아 확인하지 못했습니다. 위 비교는 결과만 봅니다.
- 시간은 공유 클라우드 컨테이너에서 쟀으므로 다른 기계에서는 배율이 달라질 수 있습니다.
