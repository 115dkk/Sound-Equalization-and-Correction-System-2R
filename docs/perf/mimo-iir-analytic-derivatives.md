# MIMO IIR 해석적 미분 실험

v0.26.0의 리소스 최적화에서 뺀 변경 가운데 MIMO IIR의 해석적 미분을 다시 판정할 수 있게 모아 둔 문서입니다. 시뮬레이션 게이트에서는 탈락했지만 실제 방에서는 아직 재생해 본 적이 없으므로, 다른 세션이 이 판을 실제로 재생해 Dirac Live ART의 실측과 비교한 뒤 채택 여부를 정할 수 있게 했습니다. 바뀌는 식, 제외한 근거, 지금까지 잰 값, 패치 적용 방법, 실측 비교 절차를 차례로 적습니다.

패치는 [`mimo-iir-analytic-derivatives.patch`](mimo-iir-analytic-derivatives.patch)이고, 기준은 main의 c15e48a(v0.27.3)입니다. 이 문서의 수치는 모두 그 기준판과 패치를 얹은 판을 이 저장소의 골든 사례로 돌려 얻었습니다.

## 1. 무엇이 바뀌는가

MIMO IIR은 주 채널 하나를 재생할 때 다른 스피커(서포트)가 보정 신호를 함께 내서 20–150 Hz의 늦은 에너지를 줄입니다. 서포트 경로 하나의 전달함수와 변수는 아래와 같습니다.

```text
H(f) = 10^(g/20) · polarity · exp(-j·2π·f·τ/1000) · Π_k P_k(f) · Π_a A_a(f)

x = [g(dB), τ(ms), (ln f0, ln Q, G dB) × K개 PEQ, (ln f0, ln Q) × A개 올패스]
```

`P_k`는 48 kHz RBJ 피킹 필터, `A_a`는 아날로그 2차 올패스입니다. 변수를 맞추는 최적화는 두 번 있습니다.

- **시드 맞춤(`fit_one`):** 서포트 경로 하나를 혼자 목표 응답에 맞춥니다. 경계가 있는 TRF이고 평가 한도는 300회입니다. main은 SciPy `least_squares`의 기본값과 같은 2점(전진) 차분으로 Jacobian을 만듭니다.
- **결합 맞춤(`solve_joint`):** 모든 서포트를 함께 맞추고, 잔차는 위치별 늦은 에너지, 노력, 레벨, 이득 항입니다. 평가 한도는 `Tuning::mimo_max_nfev`(기본 150회)입니다. main은 업스트림 `mimo_iir.py`와 같이 PEQ·올패스 변수를 h=10⁻⁴ 중앙차분으로 미분하고, 이득과 지연 열은 원래 해석적입니다.

패치는 두 맞춤 모두에서 PEQ와 올패스 인자의 로그 미분 `(1/P)·∂P/∂θ`를 닫힌 식으로 계산하고 `∂H/∂θ = H · (1/P)·∂P/∂θ`를 씁니다. 목적함수, 경계, 평가 한도, TRF 반복은 그대로이고 미분만 바뀝니다. 시드 맞춤은 같은 TRF 반복에 Jacobian을 넘기는 `optimize::least_squares_analytic`을 씁니다.

### 피킹 PEQ

`a = 10^(G/40)`, `w = 2π·f0/fs`, `α = sin w / (2Q)`, `z = exp(-j·2π·f/fs)`, `u = 1 - z²`라 두면 RBJ 계수의 분자와 분모는 다음과 같습니다.

```text
N(z) = (1 + α·a) - 2·cos w · z + (1 - α·a)·z²
D(z) = (1 + α/a) - 2·cos w · z + (1 - α/a)·z²
```

로그 미분은 `∂N/N - ∂D/D`이고, 각 변수의 `∂N`, `∂D`는 아래와 같습니다.

| 변수 | ∂N | ∂D |
|---|---|---|
| ln f0 | `α_f·a·u + m_f·z` | `α_f/a·u + m_f·z` |
| ln Q | `-α·a·u` | `-α/a·u` |
| G (dB) | `(ln 10/40)·α·a·u` | `-(ln 10/40)·α/a·u` |

여기서 `α_f = w·cos w / (2Q)`는 `∂α/∂ln f0`, `m_f = 2w·sin w`는 `∂(-2 cos w)/∂ln f0`입니다. 분자와 분모를 따로 나누므로 아주 작은 대역 응답으로 전체 곱을 나누는 일이 없습니다. 구현은 `secs_dsp::response::peaking_log_derivatives_z`입니다.

### 아날로그 올패스

`s = j·f/f0`, `N = s² - s/Q + 1`, `D = s² + s/Q + 1`이면 다음과 같습니다.

```text
∂ln A/∂ln f0 = (-2s² + s/Q)/N - (-2s² - s/Q)/D
∂ln A/∂ln Q  = (s/Q)/N - (-s/Q)/D
```

올패스는 크기가 1이므로 이 미분의 실수부는 0입니다. 패치의 단위 테스트가 이것을 확인합니다. 구현은 `secs_dsp::response::allpass_log_derivatives`입니다.

## 2. 미분 자체는 더 정확합니다

`room_C`의 기록된 결합 문제에서 해석적 JᵀJ와 중앙차분 JᵀJ를 비교하면, f64에서는 h를 줄여도 차이가 줄지 않습니다. 48 kHz 저역 RBJ 계수 합에서 자릿수가 사라지기 때문입니다. 인자 응답만 확장 정밀도(`longdouble`, ε≈1.08×10⁻¹⁹)로 계산하면 차이가 h²에 맞춰 줄어듭니다. 그러므로 기존 오라클(h=10⁻⁴)과 해석적 미분의 차이 2.69×10⁻⁶은 중앙차분의 절단오차입니다.

| 중앙차분 h | f64 JᵀJ와 해석적 JᵀJ의 상대 최대 차이 | 인자만 확장 정밀도로 계산한 차이 |
|---:|---:|---:|
| 10⁻⁴ | 2.69×10⁻⁶ | 2.67×10⁻⁶ |
| 10⁻⁵ | 3.36×10⁻⁷ | 2.65×10⁻⁸ |
| 10⁻⁶ | 3.24×10⁻⁶ | 9.86×10⁻¹⁰ |

재현은 `python3 docs/perf/resource-iir-derivative-check.py`이고 결과 표본은 [`resource-iir-derivative-check.json`](resource-iir-derivative-check.json)입니다(NumPy 필요). 이 컨테이너(Python 3.13, NumPy 2.5.3)에서 다시 돌려도 표본과 같은 값이 나왔습니다.

Rust 쪽에서도 같은 차이가 나옵니다. 패치를 얹은 `mimo_iir_functions_match_dense_oracle`은 중앙차분 이식이 오라클을 10⁻¹⁰ 안에서 재현하는지 먼저 확인하고, 해석적 미분의 차이를 따로 잽니다. room_C의 JᵀJ 차이는 2.687×10⁻⁶으로 파이썬 진단과 같고, 6개 사례의 최대는 room_L의 2.92×10⁻⁵입니다. 테스트 상한은 이 최댓값의 1.5배입니다.

## 3. 시뮬레이션 게이트에서 탈락한 근거

### 결합 맞춤 비용

`mimo_iir_joint_costs_within_spread`는 기록된 같은 시작점에서 결합 맞춤을 풀고, 끝 비용이 SECS 2 기준 실행과 다른 5벌의 분포 안에 드는지 봅니다. 비용은 낮을수록 좋습니다.

| 사례 | main(중앙차분) | 패치(해석적) | SECS 2 기준 | SECS 2 다른 5벌 | 상한 |
|---|---:|---:|---:|---:|---:|
| room_C | 1.0199×10⁻² | 1.0259×10⁻² | 1.0269×10⁻² | 1.0130–1.0283×10⁻² | 1.0460×10⁻² |
| room_L | 7.142×10⁻³ | **7.376×10⁻³** | 7.152×10⁻³ | 7.146–7.262×10⁻³ | 7.298×10⁻³ |
| room_R | 6.838×10⁻³ | 6.961×10⁻³ | 6.835×10⁻³ | 6.835–7.028×10⁻³ | 7.077×10⁻³ |
| room_dba_C | 1.1031×10⁻² | 9.335×10⁻³ | 9.926×10⁻³ | 8.415–11.306×10⁻³ | 1.3540×10⁻² |
| room_dba_L | 9.363×10⁻³ | 9.493×10⁻³ | 9.878×10⁻³ | 9.272–10.074×10⁻³ | 1.0881×10⁻² |

room_L이 상한을 넘고 SECS 2의 6벌 모두보다 나빠서 이 게이트가 실패합니다. 나머지 다섯은 상한 안이지만 방향이 일정하지 않습니다. main보다 낮아진 사례는 room_dba_C와 room_dba_R 둘이고 넷은 높아졌습니다.

방향이 일정하지 않은 까닭은 결합 맞춤이 수렴하기 전에 평가 한도에서 멈추기 때문입니다. 두 판 모두 모든 사례에서 평가 150회를 다 쓰고 SciPy 상태 0(평가 한도 도달)으로 끝났습니다. 끝 비용이 궤적에 따라 정해지므로, 미분이 정확해져도 같은 예산에서 끝 비용이 늘 낮아지지는 않습니다.

### 늦은 에너지

전체 MIMO 실행(`mimo::run::compute`)을 같은 설계 결과에서 두 판으로 돌려 주 채널마다 늦은 에너지를 쟀습니다. 늦은 에너지는 `decay::late_db_20_150`입니다. 응답에 4차 버터워스 20–150 Hz 대역통과를 걸고, 도착 뒤 150–400 ms 에너지를 처음 50 ms 에너지와 비교한 dB입니다. 아래 표의 감소량은 MIMO 뒤 값에서 앞 값을 뺀 것이라 음수가 클수록 좋고, 차이는 패치에서 main을 뺀 값이라 음수면 패치가 낫습니다.

## 4. 패치 적용

main의 c15e48a에서는 그대로 적용됩니다.

```sh
git apply docs/perf/mimo-iir-analytic-derivatives.patch
```

패치가 바꾸는 파일은 셋입니다.

- **`crates/secs-dsp/src/response.rs`:** `peaking_log_derivatives_z`와 `allpass_log_derivatives`를 더하고, 두 미분을 중앙차분과 비교하는 단위 테스트를 더합니다.
- **`crates/secs-engine/src/mimo/iir.rs`:** 시드 맞춤에 Jacobian 클로저를 더해 `least_squares_analytic`으로 풀고, `Parts::derivatives`가 해석적 미분을 채웁니다. 업스트림 중앙차분 `finite_difference_derivatives`는 테스트 전용으로 남고, 테스트가 오라클과 비교할 때 쓰도록 `Objective::use_finite_differences`를 더합니다.
- **`crates/secs-engine/src/tests/mimo_iir.rs`:** 오라클 검사가 중앙차분 이식과 해석적 미분을 따로 확인합니다.

main이 더 움직여 패치가 적용되지 않으면 위 네 자리만 손으로 옮기면 됩니다. 옮긴 뒤에는 3절의 늦은 에너지 표가 같은 값으로 나오는지 먼저 확인하십시오. 다른 변경이 MIMO 입력을 바꾸지 않았다면 비트까지 같아야 합니다.

패치를 얹은 판에서 실패하는 테스트는 아래와 같습니다. 이 실험판은 앱과 CLI를 빌드해 실측에 쓰는 용도이니, 이 상태로 main에 머지하지 마십시오.

- **`secs-engine::tests::mimo_iir::mimo_iir_joint_costs_within_spread`:** room_L의 결합 맞춤 비용이 상한을 넘습니다(3절).

패치는 앱 설정이나 IPC를 바꾸지 않으므로, 이 판으로 빌드한 앱과 CLI는 MIMO IIR을 켤 때 항상 해석적 미분을 씁니다. 기준판(main)과 실험판을 따로 빌드해 같은 측정에서 각각 보정값을 내보내십시오.

## 5. Dirac Live ART와 실측 비교

Dirac이 공개한 설명으로는 ART가 20–150 Hz에서 동작하고, 모든 스피커와 방을 하나의 MIMO 시스템으로 다뤄 저음이 남는 시간을 줄입니다([Denon의 Dirac Live 설명서](https://manuals.denon.com/DiracLive/ALL/EN/DRDZSYeewuvdnn.php), [StereoNET의 Dirac 인터뷰](https://www.stereonet.com/uk/features/inside-track-dirac-live-active-room-treatment/)). SECS 2R의 MIMO IIR도 같은 대역(늦은 에너지 대역통과 20–150 Hz, `fsiso` 기본 150 Hz)에서 같은 일을 하므로 같은 지표로 바로 비교할 수 있습니다. ART의 내부 알고리즘은 공개되지 않았고 이 저장소에서 확인하지 않았습니다.

### 조건

같은 방, 같은 스피커 배치, 같은 마이크와 청취 위치에서 아래 네 조건을 재십시오.

| 조건 | 만드는 방법 |
|---|---|
| 보정 없음 | 처리 없이 재생 |
| SECS 2R 기준판 | main으로 빌드한 앱이나 CLI에서 MIMO IIR을 켜고 내보낸 설정 |
| SECS 2R 실험판 | 이 패치를 얹어 빌드한 앱이나 CLI에서 같은 측정, 같은 설정으로 내보낸 설정 |
| Dirac Live ART | Dirac 프로세서에서 ART를 켠 상태 |

두 SECS 판은 같은 측정 파일에서 계산하십시오. Dirac으로 잰 측정을 쓰려면 `.liveproject`를 SECS 2R로 가져올 수 있습니다([`DIRAC_LIVEPROJECT.md`](../DIRAC_LIVEPROJECT.md)). 가져온 IR에는 Dirac의 마이크 보정이 이미 들어 있고, 도착 뒤 약 0.43 s까지만 저장되어 있습니다. 늦은 에너지 구간(도착 뒤 150–400 ms)은 이 안에 들어가지만, 잔향이 긴 방이라면 IR 끝에서 잘린 값을 봅니다.

SECS 쪽 재생에는 CamillaDSP나 Equalizer APO로 내보낸 설정을 쓰고, 재생 레벨은 네 조건에서 같게 맞추십시오.

### 지표

실측 IR에서 위치마다, 주 채널마다 아래 값을 구하십시오. 첫 지표가 SECS의 목적함수와 정의가 같으므로 핵심 지표입니다.

- **20–150 Hz 늦은 에너지:** `late_db_20_150`과 같은 정의입니다(4차 버터워스 20–150 Hz, 도착 뒤 150–400 ms 대 처음 50 ms의 dB). 주 채널 하나를 재생할 때 MIMO 서포트도 함께 나와야 하므로, 보정을 켠 상태에서 채널을 하나씩 재생해 재십시오.
- **1/3 옥타브 감쇠 시간:** 20–150 Hz의 T20 또는 T30입니다.
- **크기 응답:** 20–150 Hz에서 목표 곡선과의 차이입니다.
- **군지연:** 20–150 Hz 군지연이고, 폭포 그림도 함께 남기면 비교하기 쉽습니다.

### 판정

사용자가 정한 기준은 Dirac ART와 더 비슷한 실측 결과를 내는 쪽을 택하는 것입니다. 이것을 숫자로 정하려면 위치·채널·대역마다 `|SECS 지표 − ART 지표|`를 구해 기준판과 실험판을 비교하십시오.

판정 전에 두 가지를 정해 두어야 합니다.

- **측정 반복 폭:** 같은 조건을 최소 세 번 다시 재서 지표가 얼마나 흔들리는지 구하십시오. 두 판의 차이가 이 폭보다 작으면 무승부입니다.
- **사례 수:** 시뮬레이션에서 해석적 미분은 채널마다 좋아지기도 나빠지기도 했습니다(3절). 방 하나, 위치 하나의 결과는 우연일 수 있으니 위치를 여럿 쓰고, 할 수 있으면 방이나 배치를 바꿔 다시 재십시오.

### 채택한다면

실측에서 실험판이 이기더라도 이 패치를 그대로 머지하면 `mimo_iir_joint_costs_within_spread`가 실패합니다. 이 게이트의 상한을 조용히 넓히지 말고 아래 순서로 넣으십시오.

1. ADR 0004의 판정 규칙에 예외를 두는 ADR을 먼저 쓰십시오. 실측 비교의 조건, 지표, 결과를 근거로 남기고, 이 편차는 SECS 2의 결과 분포 대신 실측으로 판정한다고 적으십시오.
2. `docs/DEVIATIONS.md`에 편차 번호를 새로 받아 적고, 결합 맞춤 비용 게이트를 그 ADR에 맞게 바꾸십시오.
3. 해석적 미분 테스트를 `features.toml`에 등록하고, CHANGELOG에 사용자에게 달라지는 점(MIMO IIR 결과가 바뀜, MIMO 계산이 약 15% 빨라짐)을 적으십시오.

## 6. 확인하지 못한 것

- 실험판으로 만든 보정값을 실제 방에서 재생한 적이 없습니다. 3절의 값은 모두 골든 사례의 측정으로 계산한 시뮬레이션입니다.
- 골든 사례는 MIMO IIR 전체 실행 4개(room, room_dba, room_filters, room_multi)와 결합 맞춤 기록 6개뿐입니다.
- Dirac ART의 내부 동작과 목적함수는 공개되지 않아 확인하지 못했습니다. 위 비교는 결과만 봅니다.
- 시간은 공유 클라우드 컨테이너에서 쟀으므로 다른 기계에서는 배율이 달라질 수 있습니다.
